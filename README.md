# 交易世界 · 基于主体建模的人工加密市场

> 检验一个具体问题：**简单主体的局部交互，能否涌现出真实加密市场的统计特征？**
>
> 依据：`../交易世界实例化：基于主体建模(ABM)施工蓝图.md`

---

## 这不是什么

先划清边界，避免误读：

| 不是 | 为什么 |
|---|---|
| 价格预测器 | 收益率几乎无自相关是**做对了**的特征，有可预测性反而是模型坏了 |
| 可交易信号的来源 | 模拟里的"真实价格"是内生的，没有外部真值可以对赌 |
| "校准好的模型" | 只有价格序列的统计特征有真实靶子；价差、深度、单笔流量都是内生量 |
| 完整市场模型 | 没有 ADL、保险基金、跨保证金、资金费率、隔夜跳空 |

## 这是什么

一套**理解力的工具**，同时也是**一个策略实验台**：

1. 把"肥尾""波动率聚集""清算冲击"这些现象拆到最简的生成机制上，
   逐个确认**哪个机制负责哪一项特征**。
2. 让研究者写一个策略（实现一个 `on_tick(ctx)` 方法），
   在**响应式**市场里跨 5 种市场状态、多种子跑 A/B 对照，
   并给出**成交质量归因**（赚的是价差还是接了有毒的单）。

蓝图的成功标准是：模拟输出的统计特征在**数量级**上逼近真实 BTC，
不要求逐笔吻合。产出是"哪些机制是必要的"，不是"数字对上了"。

## ⭐ 验收标准（2026-09-20 变更：数值目标 → 方向性判据）

**旧口径**：要求冲击律指数 **k 接近 0.5**（平方根律）。
**新口径**：只要求 **k 的 95% 区间排除 0.5**，即**确认显著偏离平方根律**（方向性判据）。

**为什么改**（完整依据见 **`docs/验收标准变更说明.md`**）：

- 「k **精确**逼近 0.5」在当前装置下**做不到**——判定「是否落在 0.5±0.1」
  需要约 **300 个种子**，而同装置算出的 19/19 个臂的区间全都包含 0.5；
- 「是否**显著偏离**平方根律」**做得到**——回填到「8 种子 × 未饱和档」后，
  9 个家族里 **6 个的 CI 排除 0.5**。

配套的**装置性要求**（可事先检查，不必等结果）：

1. 参与拟合的**未饱和档位 ≥ 4 档**（df ≥ 2 ⇒ t 临界值 4.30，而非 3 档时的 12.71）；
2. **最大档位的 |t| 明确显著**；
3. 标定窗口 = 实验窗口（第六条纪律）。

⇒ **这意味着下表里「k 反而更远离 0.5」这类表述要按下述方式读**：
它只说**点估计**更远离，**不等于**「更差」或「结论成立」——
要按新口径看 CI 是否排除 0.5。历史表述与更正说明见
`docs/历史数值陈述分辨力清单.md`。

## 二期（第二阶段）加了什么

一期检验了「简单主体交互能否涌现真实市场的统计特征」。
二期（指导书 `../交易世界 · 二期完整执行指导书.md`）在其上依次加了七块机制。
**只有一块达到验收线**——这个比例本身就是结论；
⚠️ 其中「长记忆订单流」那一块的验收口径是**旧标准**（k 接近 0.5），
按新标准应重读为「CI 是否排除 0.5」，详见上节与
`docs/交易世界二期-交付报告.html` 的更正块。

| 阶段 | 加了什么 | 结果 |
|---|---|---|
| 5 永续合约 | 双通道资金费率（溢价 + 订单流拥挤度）+ 交易所虚拟账户 | ✅ 年化 1.27×、正占比 0.907（靶子 0.858） |
| 6 长记忆订单流 | 元订单拆分执行 + 流动性提供者的方向性稀疏挂单 | ⚠️ 记忆确实变长了；**主指标 k 反而更远离 0.5** |
| 7 反身性 | ε-greedy bandit 主体 + 固定策略采用者扫描 | ✅ 配对设计成立；**但「已知有效的策略」这个前提不成立**（动量夏普为负） |
| 8 Hawkes 到达 | 自激点过程决定每 tick 有多少主体能出手 | ✅ 聚集性随分支比单调上升（LB Q 1127 → 5220） |
| 9 多资产 | 公共因子驱动的相关市场 + 配对交易者 | ⚠️ 相关性有解析靶子；**传导幅度未可靠测量**（缺配对反事实） |
| 10 统一校准 | MSM 矩量距离 + 块自助法参数区间 | ⚠️ 框架可用；**实测块自助法对 ACF 型矩严重低估**（恢复 0.9%） |
| 11 至暗时刻 | 多资产 + 拥挤交易 + 费率高位 + 清算触发 | ⚠️ 逐环节配对判定；暴露了「阶段5 杠杆 + 无强平引擎 → 爆仓」 |

二期在工程上最值得记的三条（都会**静默给出错误结论**，详见报告第 11 节）：

1. **排序键里的 nan 会劫持 argmin** —— `min(..., key=dist)` 遇到 nan 保留第一个元素。
2. **「机制关闭」的对照组其实开着** —— Mixin 没收到配置时用默认值（即开着），
   而症状是"两组数字一模一样"，看起来像"机制无效"。
3. **判据写成恒真命题 = 没有验收** —— 指导书预期"基线 ACF≈0"，实测基线 ACF≈0.14；
   照抄"从 0 变正"当判据等于没验收。

## 策略实验台：能检验什么

| 能做 | 说明 |
|---|---|
| 响应式环境下的策略表现 | 你的单会改变盘口、别人会对你反应——**历史回测做不到** |
| 极端状态下的稳健性 | 高波动 / 清算冲击 / 流动性枯竭，可按需生成并反复重跑 |
| **成交质量归因** | 赚的是价差，还是承受了逆向选择？（markout） |
| **PnL 来源分解** | 钱是策略赚的还是行情给的？三项之和**精确等于**权益变化 |

| 不能做 | 原因 |
|---|---|
| 预测未来收益 | 模拟里没有外部真值 |
| 直接外推到真实市场 | 冲击形状、清算机制与真实有明确差距（见报告 8.8 与 13.6） |
| 替代历史回测 | 偏差方向不同，应**互补使用** |

**必须一起报的局限**：本模型的清算冲击是线性/超线性的，真实市场是凹的（平方根律），
所以**大单成本会被高估**；没有手续费/资金费率；没有 ADL/保险基金；
主体同质且规则固定；1 tick ≈ 1 小时只是刻度不是真实时序。

## 行情数据库：真实 / 历史 / 自生成，一个 schema

```bash
python scripts/data_cli.py list                      # 库里有什么
python scripts/data_cli.py fetch --inst BTC-USDT-SWAP --bar 1H --days 90   # 联网按需拉
python scripts/data_cli.py snapshot --inst BTC-USDT-SWAP                   # 资金费率/未平仓量/标记价
python scripts/data_cli.py synth --n 2000 --seed 0   # 离线生成自测试三件套
python scripts/data_cli.py ledger -n 20              # 拉取账本
```

**三种来源共用一套表**，只多一列 `source`：

| 来源 | 用途 | 可复现性 |
|---|---|---|
| `okx` | 真实盘面 / 历史 | **入库后不覆盖** ⇒ 事后可复现 |
| `synthetic` | 压力测试 / 反事实 | **完全可复现**（同 seed + 同参数） |

⭐ 共用 schema 是刻意的：Agent 的**同一套策略代码**要在三源上跑出可对比的结果；
若三源走三套接口，「策略在真实数据上表现不同」到底是策略的问题还是接口口径的问题，
就分不清了 —— 与「同一个量不要有两条路径」是同一条纪律。

### 三条不可动摇的约束

1. **决策路径只读库**。联网只发生在「会话开始前」的准备阶段。
   决策期间联网 = 引入不可复现性 + 可能读到未来数据。
2. **入库后不覆盖**（除非显式 `overwrite=True`）。保证「当时的决策看到哪版数据」
   事后有确定答案，哪怕交易所之后修正了历史。
3. **拉取必须记账**（`fetches` 表），**失败也记**。没有账本，半年后没人知道
   某根 K 线是从哪个端点、什么参数拿的 —— 而 OKX 的 `candles`（热缓存）
   与 `history-candles`（冷存储）**可能返回不同的修正后数据**。

### 按需拉取（不预下载全市场）

```
「要交易 BTC-USDT-SWAP」→ 查库够不够 → 不够才联网 → 幂等 UPSERT + 记账
                                              ↓
                                     会话开始后**全程只读库**
```

第二次对同一范围调用 `fetch` 会返回 `(cached)`、**0 次网络请求**（已实测）。

### 自生成数据：本项目最大的优势

引擎已经在那儿了。价值不在于「造更多数据」，而在于造**已知 ground truth 的对照**：

| regime | 它回答的问题 |
|---|---|
| `normal` | **零可预测性** —— 策略在这里赚钱 = 运气或泄漏，**不可能是本事** |
| `trend` | **有方向可抓** —— 若策略在这里也没反应，说明它根本没在看价格 |
| `vol_cluster` | **波动率突变** —— 风控会不会失效 |

三件套**共享初始条件**（同 seed / 同起点 / 同价格），差别只在生成机制。

⭐ **真实数据永远给不了 `normal` 这个保证** —— 真实市场里你无法排除
「那个时期确实有可预测性」。所以这条基准是**真实数据不可替代**的。

⚠️ 三件套的 `inst_id` 会带 regime 后缀（`SYNTH-BTC__normal` 等）。
必须这样：三份世界时间轴完全相同，若共用 `inst_id`，主键
`(source, inst_id, bar, ts)` 会撞，`INSERT OR IGNORE` 会**静默丢掉后两份**
（实测踩到：三个 regime 只剩一个，且不报错）。

### OKX 公开端点的两个坑（已查证，写在这里免得再踩）

1. **分页参数命名反直觉**：`after` 传时间戳返回的是**比它更早**的数据、
   `before` 返回**更新**的。倒推历史用 `after` 翻页，两者**不能同时传**。
   翻页取上批最旧 `ts − 1ms` 作为下一次 `after` —— **减 1ms 是必须的**。
2. **`confirm='0'` 表示这根 K 线还没走完**。`load_candles` **默认过滤**它们：
   让未走完的根流进策略，等于**让策略读到未来**。

## ⭐ LLM 交易 Agent 的地基（A1 订单模型 / A2 留痕与风控）

这一层与「用不用 LLM」无关——**它是任何自动化交易系统都要有的两块地基**。
`tw/market.py` / `tw/types.py` / `tw/engine.py` **一个字没改**，
A1/A2 全是新模块，因此它们的全部行为可独立验证（无网络、无 key、无市场也能测穷）。

### A1：OKX 风格订单模型（`tw/order_model.py`）

| 概念 | 本项目的表示 |
|---|---|
| `tdMode` | `cash` / `cross` / `isolated`（构造期校验：`cash` 不接受杠杆） |
| `posSide` | `net` / `long` / `short` |
| `ordType` | `limit` / `market` / `post_only` / `ioc` / `fok` |
| `reduceOnly` | 方向同向 **拒**；无仓位 **拒**；超量 **裁剪** |
| `attachAlgoOrds` | `AlgoOrder`，默认 `triggerPxType="mark"`（**防插针**） |

**拒单码用 `TW-` 前缀**（`TW-1001`~`TW-1010`），**不复用真实 OKX 的数字码**
——否则"本项目拒的"和"交易所拒的"在日志里无法区分。

⚠️ **触发方向必须按开仓方向取反**：多头 tp 用 `>=`、sl 用 `<=`；
空头**相反**。写成一个方向会让空头的止盈在价格**上涨**时触发
= 把止盈做成**立即触发的止损**，比不设更糟。已开 M64 变异体守住。

### A1：保证金账户账本（`tw/account.py`）

- **分档 MMR**（4 档递增）、**maker/taker 分开计费**（费差 2.5 倍，
  这就是 `post_only` 的价值来源）
- `Position.apply_fill` 覆盖四种情形：空仓开仓 / 同向加权 /
  反向部分平 / **穿仓反手**（最易漏的一种）
- **强平价分母多空不同**：多头 `(avg·q − cash)/(q(1−m))`，
  空头 `(avg·q + cash)/(q(1+m))`。抄成一个分母 ⇒ 空头该强平时看起来安全。
- **不变量**：现货 `available_cash >= 0`；永续 `equity >= 0`（cash 可为负）
- **`apply_fill` 只加盈亏、不减名义价值**——这是"杠杆"的本质

⚠️⚠️ **`margin_ratio` 的读法**：本模块用
`(权益 − 维持保证金) / 名义价值`，这个口径下 **ratio 越小越危险**。
反直觉之处在于**价格下跌时 ratio 会变大**（分子分母同时缩小、
分母缩得更快）。实测：持仓 1 BTC @100 / cash=10，
mark=110 → ≈9.996；mark=95 → ≈90.996。
所以**不要用"ratio 上升"判断变安全**——用 `is_liquidated`。

### A2：决策留痕（`tw/decision_log.py`）

按**证据链六项**组织，每一项都有对应字段：

| # | 要回答的问题 | 字段 |
|---|---|---|
| ① | 决策时能看到什么 | `visible_state` / `data_snapshot` / `context_hash` |
| ② | Agent 相信什么 | `prompt_template` / `model` / `model_params` / `tool_calls` / `retrieved` |
| ③ | 建议的动作 | `llm_raw`（**不截断**）/ `n_samples` / `samples` / `parsed` / `parse_ok` |
| ④ | 建议是否真的变成交易 | `requested`（**风控前**，必须保留）/ `executed` / `order` / `reject_code` |
| ⑤ | 什么规则接受/拒绝/改了量 | `risk`（= `RiskDecision.to_dict()`） |
| ⑥ | 扣掉成本后的结果 | `outcome` / `outcome_filled` |

**三条硬约束**：

1. **`decision_id` 必须确定性**：sha256 只含
   `run_id / tick / agent_id / prompt_template / model / context_hash`。
   `wall_ms` / `latency_ms` / `outcome` **不能进**——
   它们每次不同，进来就会让"同一次决策算出不同 ID"，回放核对直接失效。
2. **可见状态的签名上没有 `future_*`，且 `**extra` 的键名受守卫** ——
   只从**函数签名**上堵住答案泄漏是不够的：`**extra` 是一个不受限入口，
   `build_visible_state(mid=1, fundamental=1, future_close=999)` 就能把
   未来数据塞回去，签名上"没有 `future_*` 参数"的承诺会被整个架空。
   守卫因此落在**键名**上（`_is_leaky_key`）：以
   `future` / `outcome` / `lookahead` / `hindsight` **开头且在词边界**的键
   一律 `ValueError`。⚠️ 词边界是必需的——`futures_basis`（期货基差，
   决策当时真的能看到）不能被误杀；一个误杀过多的守卫最后会被人整体关掉。
   已开 M77 变异体守住（见下）。
3. **JSONL 只追加**：`open(mode="w")` 直接 `ValueError`。

体检指标（`log_stats`）都是**直接可观测量**，不是拟合出来的刻度：
`parse_ok_frac` / `executed_frac` / `abstain_frac` / `resized_frac` /
`rejected_frac` / `incomplete_visible_frac` / `latency_ms_p50` …
**留痕质量不会自动体现在收益上**（一个"只记成功解析"的实现收益更好看），
所以必须独立报告。

另有 `decision_stability`（多采样一致性——实测 Agnes 在
temperature=0.2 下三次调用给出 1 sell / 2 hold，mean_consistency=0.667）
与 `risk_contribution`（**风控贡献归因**：`median_size_ratio` + `by_rule`）。

### A2：风控闸门（`tw/risk.py`）

它只吃一个 `dict`（模型解析出来的意图），**不依赖 LLM、不依赖账户对象**，
所以能在最便宜的环境里把全部分支测穷。

| 检查 | 结果 |
|---|---|
| action 非法 / mid 无效 / sz·px·tp·sl 不可解析或非正 | **拒** → 退回 hold |
| 委托价或 TP/SL 偏离 mid 超 `max_tp_sl_pct` | **拒**（⭐ 拦第 6 轮实测的 100 倍量级错误） |
| TP/SL 在 mid 的错误一侧 | **拒**（反了会立即触发） |
| 杠杆非法 / 超限 | **拒** |
| 持仓数 / 单标的敞口 / 保证金 | **拒** |
| 量超上限 | ⭐ **裁剪**（唯一会改量的一步） |

**边界 = 「能不能推出意图」**：意图明确（量大了）→ 裁；
语义错误（方向错 / 数值非法）→ 拒。
这与 `apply_reduce_only` 是同一条边界。

⚠️ **裁量必须排在敞口/保证金之前**（顺序不是风格问题，是**可达性**问题）：
先判敞口的话，"买 1000"这种"想大了"的单会被 `exposure_cap` 抢先拒掉，
`size_cap` 的裁剪分支**永远走不到**——成了不可达代码，且不报错、不警告。
用**裁剪前的量**算敞口，等于拿一个不会发生的订单去拒绝一个会发生的订单。

**执行顺序**：`hold → action → mid → sz → px → TP/SL → 杠杆 →
⭐ 量上限(裁) → 持仓数/敞口 → 保证金`。

## 设计约束与工程纪律（十条，都是踩出来的）

### 1. 只留一条记账路径

`Market` 是全项目唯一允许改动账户的地方。踩过的坑：`MatchingEngine` 里留了
`trade_sink` 钩子，但 `Market.submit` 忘了接上——**撮合一直正常成交，日志里却一笔都没有**，
表现为"价格序列正常、成交数 0"，市场静默冻结。现在成交只由 `Market.submit` 显式落账。

### 2. 价格必须吸附到 tick 网格

订单价格用未对齐的浮点值挂单、而订单簿按 tick 网格价成交，
会造成**预留按原价算、结算按网格价付**，四舍五入方向不定 → 每笔成交泄漏一点点，
跑几千 tick 后账户守恒被破坏。现在 `Market._clamp` 第一步就把价格吸附到网格。

### 3. ⭐「主体数量」必须与「背景行情」解耦

这条是做策略实验台时才发现的，也是最隐蔽的一条。

原来的实现用 `self.rng.shuffle(self._order)` 决定主体的出手顺序。
**洗牌的置换取决于列表长度**——于是往市场里多放一个主体，
所有主体的出手顺序会整体错位，背景行情从第 0 个 tick 就变了。

后果很具体：**注入一个"什么都不做"的策略主体，行情就已经不同了**。
拿它当对照去评估策略，测到的差异里混着"多了一个人参与洗牌"这个纯伪影。

现在的设计：
- 市场随机流**只**用于基本面价值步进；
- 主体禀赋来自**每主体独立**的随机流 `[seed, idx, ENTROPY_ENDOW]`；
- 动作顺序由**每主体独立抽的优先级**决定（`[seed, ENTROPY_ORDER, key]`）。

实测：注入一个不交易的主体后，**行情逐点最大差 = 0**（已固化为测试）。

### 4. 测量方式必须与被测现象的时间尺度匹配

这是本项目最贵的教训，同一个坑踩了五次：

| 坑 | 错误结论 | 根因 | 修正 |
|---|---|---|---|
| 用 3000 tick 窗口的最大偏离当"冲击峰值" | 卖出清算造成 **+422bp 正冲击** | 随机漂移幅度远大于冲击 | 峰值只在短窗口内取 |
| 路径从清算**结束后**才开始记 + 单种子无对照 | 幂律指数 **−0.26**（物理上不可能） | ①分期清算的峰值在清算**进行中**被漏掉 ②σ√60 的漂移淹没冲击 | 路径覆盖全程 + **同种子配对控制**（降噪 62 倍）+ 多种子 t 检验 |
| 滑点基准用**固定的**清算前价格 | 慢抛被虚报成 **−50bp** 冲击 | 抛售跨 100 tick，市场自己的漂移被算成滑点 | 基准改用**同时点的反事实价格** |
| 瞬时清算的中间价是退化值 | "市场跌了 356bp" | 盘口被打空后回退到最新成交价 | 新增无歧义的「最差成交价」指标 |
| 幂律拟合护栏太松 | k=1.72、R²=0.987 的漂亮结果 | 自变量跨度仅 0.7%，在噪声上拟合 | 增加自变量/因变量跨度护栏，拒绝时如实报理由 |

**纪律：任何"事件冲击"类测量，必须同时满足
（a）路径覆盖事件全程、（b）有配对/随机对照基准、（c）锚点是同时点的真实盘口价。
三条缺一条，结论就不许出口。**

同源问题还有一次在扫单研究里：用"扫单刚砸完那一刻的中间价"当锚，
会把**同一 tick 内**的跟风推动误读成跨 tick 的趋势（虚报 +52bp，实际 +11bp 且不显著）。
最后补上**内生性诊断**才发现整个"延续"结论是分组混合的假象——
详见报告的"扫单"一节。

### 5. ⭐ 缓存键必须覆盖「把配置翻译成行为的那段代码」

这是二期最危险的一条，因为它打击的不是某个数字，而是**整条证据链**。

阶段6 的跑场缓存键原来是 `{tag, seed, n_ticks, mix}`。看起来该有的都有了。
但被缓存的量（一场模拟的长记忆指标）还依赖**市场是怎么被装配的**——
`Stage6Market.decorate_agent` / `factory` 的行为。而那段代码里有个 bug：
对照组本应"机制全关"，却混进了 `MetaOrderMixin` 的默认 `p_meta_start=0.02`。

修掉之后重跑，产出的 k 值与修复前**逐位相同**。
而这次"相同"**当时无法被解释**：可能是修复无效果，也可能是根本没重跑。
事后核对旧缓存的键才确认是后者——那次"重跑"命中了陈旧缓存，
**在物理上不可能验证修复**（旧键 `e13b225a…` 在缓存里，带签名的键 `aa629d40…` 不在）。
根因是缓存键里**不含**"对照组是不是真的关着"这个事实，
而它**不在任何参数里**，所以键一个字符都没变。
（诚实补充：清空缓存后真正重算，E6.1 的数字与此前报出的一致，
所以这一次并没有真的产出错误数字——但当时没有任何机制能告诉我们是哪一种。）

现在的三道锁（`scripts/_cache.py`）：
1. 行为签名（参与装配的类 + 工厂 + 模块级常量 + `tw/` 源码树内容哈希）进入**每一个键**；
2. 缓存文件头记录本轮签名，**不符则整份作废**（而不是"新键查不到就用旧值"）；
3. 命中/未命中数在每次运行结束时打出来——**静默命中**是这类事故的共同特征。

配套：`tests/test_cache_keys.py` 会把源码复制一份、只改「惰性配置 → 默认配置」
那一句，断言签名必须变化。**没有这条测试，上面三个制度都只是注释。**

顺带两条同源纪律：
- **旧格式（无签名）的缓存文件一律丢弃。** 用没有签名机制的代码写出来的缓存，
  无法判断是否陈旧——宁可重算。实测两个缓存文件共 63 条，全部作废重算。
- **报告里的数字必须有独立检查。** `scripts/selfcheck.py` 只读产物、
  不看生成器代码，把报告的"承重数字"逐个与 JSON 现算值对账。
  它上线后第一个抓到的，是报告总览表里**手抄**的 `k 从 0.665 走到 0.910`
  ——抄在 3 个地方，而重跑之后一个都没动。

### 6. ⭐ 标定配置必须与实验配置**同源**，且标定窗口 = 实验窗口

（三线深挖之后追加，由工作线A 用血换来）

真实事故（E8.2）：λ̄ 在**裸 `Market`** 上标定（50.09），却在**带做市配置的市场**
上使用（真实基线 88.50，偏 **1.767×**）⇒ ρ̄ ≈ 1.48 撞上 `rho_to_count` 的上限
⇒ **稀疏化在 99.8% 的 tick 上从未发生**。
而这一点从产物里**完全看不出来**——k 确实"改善"了，极易被读成"机制生效但效果有限"。

对策（`scripts/verify_EA4_calibration.py`）——**不比对两份手抄配置**
（那也可以"看起来一样、实际不同步"），而是三步：
① 来源核对：实验侧**实际生效**的常量 vs 标定侧**收到**的 kwargs；
② 物化核对：两侧各真建一个市场，比主体构成指纹；
③ 窗口核对：标定窗口是否等于实验窗口。
任一步不干净 ⇒ 必须重标定后重测。

### 7. ⭐ 任何「从 A 变到 B」的陈述，必须同时报告它自己的置信区间

（分辨力危机那一轮新增。它的由来是一个比前六条**更根本**的问题）

诊断发现：冲击指数 k 在「4 档 × 3 种子」下**没有分辨力**——
**19/19** 个历史臂的 95% 区间都包含 0.5，16/19 连 0 都包含；
区间宽度中位数 **2.33**，而全项目讨论过的差异只有 **0.3~0.9**。

三条可搬运的判据（已沉淀进 `~/.workbuddy/skills/impact-measurement-discipline`）：
1. **先算 CI，再报差。** CI 宽度必须显著小于你要主张的差异。
2. **手算首尾斜率**，看拟合是否被两端绑架。
   （实例：`log(15.565/5.255)/log(10) = 0.472` ≈ 报出的 `k = 0.455`
   ⇒ 中间两个档位没提供任何信息。）
3. **量化 `n_need = n·(W/Δ)²`**——本例：判定「是否落在 0.5±0.1」约需 **300 个种子**
   （当时用 3 个）。这个数一算出来，就能判断这条路值不值得走。

据此：
- **新写的**陈述必须带 CI / 标准误 / 种子数，否则只能算「当次读数」，不算结论；
- 自动化检查：`scripts/audit_numeric_claims.py` 扫描全部报告里的「数值比较型」
  陈述（当前 **162** 处），标出有 CI 支撑 vs **裸奔**；
- 存量清单：`docs/历史数值陈述分辨力清单.md`。

配套的一条同样重要：把「机制体检指标」（**直接可观测量**，如稀疏化生效占比、
活跃主体数、净/总暴露）与「拟合出来的刻度」（如 k）**分开报**——
前者的证据不经过拟合，**不受此问题影响**。

### 8. ⛔ 批量替换必须先临时副本 + 语法校验（**不是建议，是硬性前置步骤**）

这条是**用两次真实事故换来的**：为修文案里的裸引号写了个「按行替换引号」的脚本，
结果把源码写坏——第二次（分辨力危机那一轮）把模块/函数 docstring 的 `"""` 改成 `"「"`、
把字典键改成 `"k「: r[」k_point「]`，而且**不报错，只是在继续制造新的语法错误**。

强制入口：`scripts/safe_batch_replace.py`（此后**任何**批量替换都走它，不许手写替换逻辑）

- 先在**临时副本**上执行（按**相对路径镜像**目录结构——用 basename 会让
  不同目录的同名文件互相覆盖，那是"校验过的内容 ≠ 写回的内容"的静默错误）
- 对每个受影响的 `.py` 跑 `ast.parse`，**任一失败则整体回滚**（部分写入比不写更危险）
- 默认 `dry_run=True`，确认后再 `--apply`

### 9. 每条工作线完成时对应一次 git commit

commit message 用 `[工作线X] 一句话结论`。目的不是引入 CI/PR 流程，
而是让**以后的任务书能精确引用「这个结论对应哪个 commit」**——
比在文件名里塞时间戳可追溯得多。

配套：**变异测试编号不再写死在任务书文字里**。
用 `scripts/claim_mutation_ids.py --claim N --by <工作线>` 动态领取，
权威账本在 `docs/mutation_registry.json`（可查"哪批编号是哪个工作线什么时候领的"）。
这条是从"任务书预写的编号与实际对不上"这个反复出现的问题上改过来的
（三线深挖、分辨力危机两轮都撞过）。

### 10. ⚠️ 「方向反转」类陈述必须走区间重叠检验（**这条是审自己审出来的**）

**任何「此前 A 更好 → 现在 B 更好」的陈述，必须用区间重叠度量正式检验。**
点估计换了方向，只能说**「新的读数如此」**；能不能说**「结论变了」**，
要看区间重叠检验的结果。

这条纪律的由来：本项目一路在纠正「**点估计冒充结论**」这个毛病，
结果在「回填标准配置」那一轮**自己又犯了一次**——
报告里写了两条「历史结论被推翻」，而它们只依据点估计的方向变化。
补做区间重叠检验后发现，那两个比较的重叠分别是 **100%** 与 **80.9%**，
**连「方向变化」都不该被当成结论**。

实现：`tw/analyzer_consistency.py`

- `ci_overlap_fraction` —— 重叠长度 / **较窄**区间的宽度（分母不能是两者之和，
  否则「100% 包含」会被算成约 50%，「无法判定」会看起来像「显著」）；
- `required_n_to_separate` —— 按「宽度 ∝ 1/√n」外推还需要多少样本
  （分母用**两区间宽度之和**，只用较窄的那个会低估）；
- `pairwise_verdict` —— 三选一判定（`显著` / `依然无法判定` / `边缘`），
  阈值 0.20 / 0.30 是**约定**不是推导，已在模块文档写明理由。

配套：**「单个家族的方向判定」与「家族之间的比较判定」是两件事**——
前者只看自己的 CI 是否排除 0.5，不受一致性审计影响；后者才受影响。

## 核心结果速览

**内核**：84 测试全绿 + 12/12 注入 bug 被抓 → 全绿是有信息量的。

**标定**：蓝图建议的报价幅度（±0.1%~2%）会让 σ 达到真实 BTC 的 **10.76 倍**；
收到 0.18% 后量级命中。且 σ 强烈依赖主体数 N——**标定必须附带 N**。

**阶段1**：零智能基线不崩溃、不发散、接近随机游走。
蓝图引用的 Gode-Sunder "收敛"在本市场**无定义**（没有外生锚）。

**阶段2（机制归因）**：
- 基本面派单独存在 → **肥尾被抹平**（峰度 5.05 → 0.23）
- 图表派单独存在 → **波动率爆炸**（σ 398bp）、强趋势（VR 4.5）
- **两者必须共存**，混合池才同时给出肥尾、波动率聚集、接近 1 的方差比

**阶段3**：
- 做市商：价差 0.53×、深度 1.60×、σ 0.55×
- **瞬时清算会饱和**：盘口深度就是清算能力的上限，超出部分不是"更差价格成交"而是"压根没成交"
- **抛售速度决定冲击**：同一笔 2% 持仓，一次砸完滑点 −170bp，拆 100 片只有 −12bp

**扫单**："扫单后继续走"成立，但时间尺度是**同一 tick 内**（约 80 笔成交），
之后 10~20 tick 内显著反转并基本抹平——**不能用来预测趋势**。

**最明确的失配**：真实市场的冲击是**凹的**（平方根律 k≈0.5），本模型给出线性。
根因已定位：**盘口累计深度剖面接近线性（γ≈1），真实市场是凸的（γ≈2）**。
→ 要复现平方根律，缺的是**远端的长记忆挂单**，不是更多主体。
