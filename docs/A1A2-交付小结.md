## 3. ⭐ 关键设计决策（这些是"和你原来想的不一样"的地方）

### 3.1 拒绝 vs 改量的边界 = 「能不能推出意图」

| 情形 | 处置 | 理由 |
|---|---|---|
| Agent 说"买 1000 手"，但账户只够 30 手 | **裁剪成 30** | 意图明确（想买），只是量大了 |
| Agent 说"止盈挂在当前价下方"（多头） | **拒单** | 语义错误——这单会立即触发，等于下单瞬间亏损平仓 |
| Agent 说"平仓 300 手"，但只有 100 手仓位 | **裁剪成 100** | 意图明确（想平掉） |

**为什么这条重要**：只有裁剪的**量**被记录下来（`resized_to`），
才能事后回答"**风控到底贡献了多少**"。如果一律拒单，
风控的贡献会被记成 0，而 Agent 看起来像"从没下过大单"。

### 3.2 风控的**步骤顺序**是可达性问题（不是风格问题）

原实现把「量上限裁剪」排在「敞口检查」**之后**，后果是：

```
Agent 说"买 1000"，账户 10,000
→ 敞口 = (0 + 1000×100)/10000 = 1000% > 60%  ⇒ 判 exposure_cap 拒单
→ size_cap 那条裁剪分支永远走不到 ⇒ 不可达代码
```

它**不报错、不警告**，只是那条分支再也不会执行。已把裁量步提到前面。
**执行顺序**：`hold → action → mid → sz → px → TP/SL → 杠杆 →
⭐量上限(裁) → 持仓数/敞口 → 保证金`。

### 3.3 `decision_id` 必须确定性

只含决策**固有**字段（`run_id/tick/agent_id/prompt_template/model/context_hash`）。
`wall_ms` / `latency_ms` / `outcome` **不能进**——它们每次不同，
进来就会让"同一次决策算出不同 ID"，回放核对直接失效。

⚠️ 特别注意 `prompt_template`：A/B 换 prompt 的实验里，
少了它两条决策会算出**同一个 ID**，归因彻底失效，而日志看起来完全正常。

### 3.4 可见状态：签名 + 键名**双重**守卫

`build_visible_state` 签名上确实没有 `future_*` 参数——
但函数还有 `**extra`，能挂 `future_close` / `outcome_pnl`，
把"签名堵住答案泄漏"这个承诺**整个架空**，而且**完全静默**。
现已在键名上加了第二道守卫（见下节）。

## 4. 施工中抓到并修掉的 **6 个真实缺陷**

这一节比"交付了什么"更重要——**每一条都是先写错了、被测试抓住的**。

| # | 缺陷 | 为什么危险 |
|---|---|---|
| ① | `margin_ratio` 口径让"下跌"看起来像"变安全" | 它是"越小越危险"，且**价格下跌时反而变大**——两个都对的东西放一起会被读反 |
| ② | 强平价分母多空抄成一个 | 空头该强平时**看起来还安全** |
| ③ | 风控步骤顺序让 `size_cap` 成不可达代码 | 不报错、不警告，分支永不执行 |
| ④ | `cash=0` 时强平价落在开仓价上方（**我的断言错了，不是代码错**） | 教训：回到**定义**去验（`equity(liq)==mm(liq)`），而不是比对期望值 |
| ⑤ | `**extra` 架空"签名堵泄漏"的设计 | **完全静默**：遍历 `sig.parameters` 的测试照样全绿 |
| ⑥ | M63 变异体"活着"了一整轮 | 弱测试与强测试**通过时长得一模一样** |

### 缺陷 ⑤ 展开（本轮最有价值的发现）

```python
build_visible_state(mid=100.0, fundamental=100.0,
                    future_close=999.0, outcome_pnl=12345.0)
# → 实测：泄漏字段真的进了 ① 可见状态
```

**修法**：保留 `extra`（自定义字段确实有用途），守卫**键名**：

```python
_LEAKY_PREFIXES = ("future", "outcome", "lookahead", "hindsight")
# 拦"以这些词开头、且在词边界上结束"的键
```

⚠️ **词边界不能省**：第一版用朴素 `startswith`，
结果 `futures_basis`（期货基差——决策当时**真的能看到**的数据）被误杀。
**一个误杀过多的守卫，最后会被人整体关掉，于是保护归零。**
这条是**被我自己写的测试抓出来的**（`test_泄漏键判定是纯函数` 一开始是红的）。

> **可复用判据**：凡是"靠签名结构来保证"的设计，
> 都要先找 `**kwargs` 逃生口。有逃生口，签名就不是约束，只是文档。

### 缺陷 ⑥ 展开（M63 为什么活下来）

M63 把 `hi = max(hi, p0, p1) * (1 + |N(0,2e-4)|)` 改成 `hi = max(p0, p1)`。
看似"K 线退化成折线"，但**已有的 `test_必须有影线` 抓不住它**：

- M63 改的是**两行里的第二行**，第一行路径极值还在；
- 而第二行的**乘性**噪声自己就让 `high > max(o,c)` 成立 ⇒ 实测 **49/49 根仍"有影线"**。

真正被破坏的性质是"影线**有多真**"（从路径极值 ~1e-3 退化成噪声地板 ~2e-4），
而测试问的是"**有没有**影线"。已补 `test_影线不是靠乘性噪声凑出来的`：
真实代码 8 个种子稳定在 **90~110 / 199**（≈45~55%），阈值取 20%；
注入 M63 后 **0 / 199**。

> **可复用判据**：「存在断言」≠「有分辨力」。弱测试与强测试**通过时长得一模一样**，
> 只有变异体能分开。**这就是必须全量跑、不能抽样跑的原因**——抽样会漏掉唯一那个漏网的。
