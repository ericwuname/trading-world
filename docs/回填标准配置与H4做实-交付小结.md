## 1. 工作线N：基础设施

### N.1 批量替换安全工具（第八条纪律的强制执行入口）

`scripts/safe_batch_replace.py` —— 先在**临时副本**上执行替换、
对每个 `.py` 跑 `ast.parse`、**任一失败则整体回滚**（默认 `dry_run=True`）。

**修掉了任务书伪代码里的一个真实缺陷**：它写的是
`Path(tmpdir) / Path(fp).name` —— 只用 basename，
两个不同目录下的同名文件会**互相覆盖**，于是「校验过的内容」与「写回的内容」可能不是同一份。
本实现按**相对路径镜像目录结构**。

13 条测试，其中最关键的一条直接复现了真实事故：
把 `"""` 换成 `"「"` 必须被拦住、抛 `UnsafeReplaceError`、且**一个文件都不写回**。

### 本轮踩到的两个环境坑（都记下来了）

1. **本环境把 `Path.unlink()` 实现成了「安全删除（移到回收站）」**。
   后果：基于 `O_CREAT|O_EXCL` 的锁文件在**并发**下会因多次 trash 同一文件而报错、且失败后**锁文件永久残留**（实测：8 个线程只成功 2 个，其余全部超时）。
   修法：Windows 上加 `O_TEMPORARY`（句柄关闭自动删除，不依赖 unlink）+ **进程内再套一层 `threading.Lock`** + 陈旧锁接管。修完 14 条测试 0.68 秒全绿。
2. scipy 的 `nct`（非中心 t）在 **大 df + 大 ncp** 下返回 `nan`，
   而 `nan < power` 为假会让二分搜索**误判「已达标」并静默给出偏小的样本量**。
   修法：`nan` 时回退到正态近似，并在反解后**复核一次**（宁可返回 `nan` = 给不出答案，也不许悄悄给一个偏小的数）。

`J1_stage6_baseline` 与 `EB1_chartist_only` 是**同一个配置**（旧读数逐位相同：k=1.2513572154501866）；

### 2.3 ⭐ EL.2：非对称是否比对称更凹（本工作线最重要的产出）

- `EA4_taker`：k = 0.734，CI = [0.5488703806412355, 1.2180467045708114]
- `EA4_both` ：k = 0.794，CI = [0.5498894324584008, 1.3780491932397092]
- 点估计差（taker − both）= -0.060
- 两区间重叠 = 0.668（较窄区间的 99.8%）

### ⇒ 判定：**依然无法判定**

⚠️ **如实报告**：即使把配置从「3 种子 × 4 档」升级到「8 种子 × 未饱和档」，这个问题**仍然判不出来**。
不能因为「投入了更多资源」就暗示「应该有答案了」——
这与阶段3 判定 k 精确值需要 300 个种子是**同一类问题**。

- **量化「为什么判不了」**：点估计差 **0.060**，较窄的那个区间宽 **0.669**。按「宽度 ∝ 1/√n」外推，要让两个区间**分开**需要约 **998 个种子**（现用 8 个）。
  ⇒ 这个效应量相对噪声太小，**不是加一点资源能解决的**，属于「方向可信、显著性做不实」的类型。

### 2.4 ⭐ 比 EL.2 本身更重要的发现：**效应量级对比**

回填后 EA.4 三臂的 k **几乎相同**（0.73 / 0.74 / 0.79，极差 0.060）。
把它和「有/无稀疏化」的效应放在一起看：

| 效应 | 幅度 |
|---|---|
| **A. 有 / 无稀疏化**（Hawkes 关 1.292 → 开 0.755） | **0.536** |
| **B. 稀疏化作用在哪一侧**（taker 0.734 vs both 0.794） | **0.060** |
| C. taker vs maker | 0.005 |

⇒ **A / B = 8.9 倍**：「有没有稀疏化」的效应比「作用在哪一侧」**大一个数量级**。

⚠️ **这意味着三线深挖的核心叙事需要修正**：那一轮说「只稀疏化吃单方最有效（k=0.455）、双边同时稀疏化互相抵消（k=0.947）」——**在回填后的干净测量里，这个区分几乎消失了**（三臂的极差只有 0.060，而噪声区间宽 0.45~0.83）。

更准确的表述是：**只要存在时间聚集性，冲击就会变凹；而它作用在需求侧还是供给侧，影响小得多。**

🔎 但要注意**同口径**：上面的 Hawkes 关基线是**现算的**（用工作线H 的 7 档 rows 跑 bootstrap），不是从旧报告抄的——
旧对照（k=1.395）是 4 档 3 种子的产物，与新口径不可直接比。

## 5. 诚实边界

1. **新旧口径不可直接比较**：回填改的是**分辨力**（种子数 + 档位数），
   不是机制。k 的变化主要来自分辨力提升。
2. **EL.2 若仍是「无法判定」，那就是无法判定**——
   不许因为投入了更多资源而暗示应该有答案。
3. **EM.4（诚实报告不显著）不是失败**：功效分析的价值就是提前算清「值不值得投入」；算出来不值得，**不投入本身就是产出**。
4. **回填只覆盖 8 个家族**（EA.4 / EB.1 / J1–J3）。
   清单里其它裸奔条目（例如阶段6/8 的历史读数）仍待后续轮次处理。
5. **EM.1 与 EM.3 的口径不同**：前者算「每组事件观测点」，后者用「跨运行的块级差」（自由度 = 运行数）。两者不可混用，所以 EM.3 里额外做了同口径反算。
