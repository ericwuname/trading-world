# A6 设计方案：从「开环决策器」到「有目标、会复盘的主体」

> 用户 2026-09-21 第五轮提出的问题（原文）：
>
> > 我在思考，如果LLM判断错误，他会怎么分析这个错误，如果判断成功，
> > 他会怎么分析这个成功，这些东西能不能作为经验呢。
> > 如果LLM喜欢用工具是因为我们给他工具，那么我们的这个工具是好工具还是坏工具呢？
> > LLM当发现自己的收益完不成目标，或者越来越差，他会想什么办法解决呢？
> > 而不是对了就对了，错了就错了，有种无所谓的感觉。
> > 是否要给LLM设计一个KPI，看看是否会有什么不同，还有不能因为达成KPI就不继续，
> > 亏损扩大就不交易，要平稳交易下去才行。
> > 你的设计该怎么实现与验证这些东西。

---

## 0. 先把问题诊断清楚

### 0.1 「无所谓」不是态度问题，是结构问题

当前的 LLM Agent 是**开环**的：

```
每根 K 线 → 看快照 → 给一个动作 → 忘掉 → 下一根重新看
```

它**不知道**：上次决策对不对、离目标多远、自己在变好还是变坏。
⇒ 它对对错"无所谓"，不是因为不在乎，而是因为**没有任何机制把结果传回给它**。

**最硬的证据**：A2 的留痕设计里，第 ⑥ 项「扣掉成本后的结果」字段
`DecisionRecord.outcome` **一直在，但从来没有人填过**（代码里是空的
`field(default_factory=dict)`）。证据链六项，实际只做到了五项。

⇒ 所以 A6 的第一件事不是"给它 KPI"，而是**先把第 ⑥ 项接上**。

### 0.2 三条已有的实测证据（说明这件事值得做）

| 证据 | 来自 | 说明什么 |
|---|---|---|
| `basis` 三类自报的**行为确实不同**（说"结合"时交易率高 17 个百分点） | 本轮交叉验证 | 它对自己的决策**有区分**，不是胡贴标签 |
| 但自报"照指标"时，动作与最简单的 momentum 信号**只有 36% 一致** | 同上 | 它的自述与外部可观测量**对不上** ⇒ 自报不可全信 |
| `v3`（给算好的指标）让它**交易更多、换手翻倍、收益反而更差** | A5 大样本 | 它会被"给它的东西"影响行为，但**影响方向未必正确** |

⇒ 后两条合起来就是用户那个问题的实证基础：
**它会用工具，但它用得对不对、工具到底帮没帮上忙，目前不知道。**

## 1. 四块设计（按依赖顺序）

```
① 结果回填  ──→  ② 复盘与归因  ──→  ③ 经验库（时间旅行安全）
      │                  │
      └──────────────────┴──→  ④ KPI 与自救行为
                                      │
                        ⑤ 度量替换（判得出来的前提）
```

⚠️ **顺序不可换**：没有 ①，②就是无源之水；没有 ⑤，④ 的结论判不出来。

---

## 2. ① 结果回填 —— 把证据链第 ⑥ 项接上

### 2.1 填什么

每条决策在它之后的 `h` 根处回填：

| 字段 | 含意 | 用途 |
|---|---|---|
| `markout_h` | 决策后 h 根的 mid 相对成交价的偏移 | 逆向选择度量（A4 已有概念） |
| `equity_after_h` | h 根后的账户权益 | 直接的"我当时做对了吗" |
| `realized_pnl` | 该笔若已平仓的已实现盈亏 | 复盘时最好懂的信号 |
| `mfe` / `mae` | h 根内最大有利/不利偏移 | 区分"方向错"与"时机错" |
| `filled` | 是否真的成交 | 区分"决策错"与"没轮到" |

### 2.2 ⚠️ 一条必须用断言守住的约束

**`outcome` 只能回填进 `rec.outcome`，绝不能进 `rec.visible_state`。**

这条**不是新写的纪律**——A3 已经用 `_is_leaky_key()` 守住了
（拦 `future_*` / `outcome_*` 等键进可见状态）。A6 要做的是：

1. 回填函数**显式断言**它只写 `outcome`；
2. 新增测试：回填前后 `visible_state` 的 `state_digest` **必须完全相同**。
   （⚠️ 这是个很强的守卫：它把"回填没污染输入"变成**机械可验证**的，
   而不是靠人记得不要手滑。）

### 2.3 回填的延迟 = 复盘的可见边界（这是后面一切的基础）

```python
def backfill(log, series, *, horizon=H):
    """只回填那些"未来已经发生"的决策。

    ⚠️ 当前时刻 t，只有 t + h <= t_now 的决策才有 outcome。
    ⇒ 这天然定义了"复盘时能看到什么"：**只有已实现的那些**。
    """
```

⇒ **这条约束让"事后诸葛亮"变成不可能**：复盘时拿不到未实现的结果。

## 3. ② 复盘与归因 —— 它会怎么分析对与错

### 3.1 触发与输入

每 `N` 根（建议 N=24，即一天）做一次复盘。

输入 = **过去 N 根的决策 + 它们的 `outcome`**（只含已实现的）。
⚠️ **不给它未来数据**——复盘的"未来"就是复盘时刻。

### 3.2 要求它输出结构化归因

自然语言理由**无法统计**。所以要求它按枚举分类：

```
对每条决策选一个"结果原因"：
  direction_wrong   方向看反了
  timing_wrong      方向对但进/出场时点不好
  size_wrong        方向对但仓位过大/过小
  should_abstain    当时该弃权却动手了
  cost_ate_it       毛赚了但成本吃掉了
  lucky             结果好但理由站不住（蒙对的）
  unlucky           理由站得住但结果差
  unclear           说不清
```

⭐ 其中 **`lucky` / `unlucky` 两项是本设计的关键**：
它们把"**结果**"与"**决策质量**"分开——
而混同这两者正是"一切以结果论"的根源。
（专业决策领域管这叫 **resulting**，是一种明确的思维错误。）

### 3.3 ⚠️⚠️ 最大的风险：事后视偏差（hindsight）经由"经验"回流

复盘时它看到了结果，所以分析必然是事后视角。**这本身不是作弊**
（它在复盘，不在决策）。危险在**下一步**：

> 如果把复盘结论**喂回决策**，就等于把未来信息注入决策。

**处置（两层）**：

| 层 | 做法 |
|---|---|
| **时间层** | 经验条目带**产生时刻** `t'`；检索时**只取 `t' < t` 的**。 |
| **内容层** | 复盘 prompt **只给到复盘时刻为止的数据**；<br>`outcome` 只含**已实现**的结果（见 §2.3）。 |

⇒ 两层合起来才是完整的：只做时间层，结论里仍可能写着"后来涨到 X"；
只做内容层，经验库仍可能被未来产生的经验污染。

### 3.4 验证（三条，都可机械验证）

| # | 验证 | 判据 |
|---|---|---|
| V1 | **回填不污染输入** | 回填前后 `state_digest(visible_state)` 完全相同 |
| V2 | **时间旅行安全** | 同一条决策，在"经验库为空"与"经验库只有 `t' > t` 的条目"两种情况下，**prompt 逐字节相同** |
| V3 | **归因有信息**（不是套话） | 同一批决策，归因分类与**可观测结果**（`realized_pnl` 符号、`mae`、`mfe`）有显著关联；<br>`lucky`/`unlucky` 两类的**理由质量**与结果**不相关**（这正是它们该有的样子） |

V2 是最强的一条：**它把"会不会泄漏未来"变成一个可以在测试里跑通的等式**，
而不是一句"我们会注意"。

## 4. ③ 经验库 —— "这些东西能不能作为经验"

### 4.1 结构

一条经验 = 「条件 + 教训」，**必须可检索、可审计**：

```jsonc
{
  "exp_id": "…",
  "created_tick": 312,          // ⭐ 时间戳：检索时用它过滤
  "condition": {"regime": "trend_up", "vol": "low"},   // 什么情况下适用
  "lesson": "12 根净变化 > 0.5% 时追多，成本吃掉大半 —— 缩小仓位或放宽阈值",
  "evidence_ids": ["…", "…"],   // 支撑它的决策 id（可回溯）
  "kind": "rule|warning|observation"
}
```

### 4.2 检索必须按时间过滤（唯一容易写错的地方）

```python
def retrieve(exp_db, *, at_tick: int, k: int) -> list[Exp]:
    # ⚠️ 这一行是本设计的**安全边界**：只用"当时已经存在"的经验
    pool = [e for e in exp_db if e.created_tick < at_tick]
    ...
```

⚠️ 朴素写法 `if e.created_tick <= at_tick` 在**同 tick 内多次决策**时会
把"本轮刚生成的经验"喂给"本轮的决策"⇒ 微小但真实的泄漏。
⇒ 用**严格小于**，并写进 docstring。

### 4.3 验证

| # | 验证 | 判据 |
|---|---|---|
| V4 | 检索的时间边界 | 构造"`t' == t` 的经验"，断言它**不出现在** t 时刻的 prompt 里 |
| V5 | **经验有没有用**（核心） | **有经验 vs 无经验**，同一段行情、同种子；看**决策质量指标**（见 §7），不只是收益 |
| V6 | 经验会不会退化成噪声 | 经验条目的**重复率**与**相互矛盾率**随时间的变化 |

⚠️ V5 的诚实预期：**很可能看不出差别**（这个领域公认）。
所以 V5 的主判据**不是收益**，而是**行为是否可归因到经验**——
比如"某条经验被检索到之后的 N 根里，相关行为的发生率是否变化"。
这比"收益变好"是一个更灵敏、也更诚实的判据。

## 5. ④ KPI 与自救行为 —— 以及两种必须防的退化

### 5.1 用户点名的两种退化（这是本设计的核心约束）

| 退化 | 表现 | 为什么会出现 |
|---|---|---|
| **达标即停**（打卡） | 一旦达标就大幅降低交易/直接停手 | KPI 被当成"及格线"而不是"持续要求" |
| **亏了就装死**（躺平） | 亏损扩大后弃权率飙升，靠零暴露避免继续亏 | **不交易就不会亏** ⇒ KPI 被"零暴露"刷分 |

⇒ 用户的要求「**要平稳交易下去**」正是对这两条的否定。

### 5.2 KPI 设计：多目标互相咬住

**单指标一定会被刷**（Goodhart），所以用一组**互相约束**的指标：

| 维度 | 指标 | 方向 | 防什么 |
|---|---|---|---|
| 收益 | 窗口净收益 | ↑ | — |
| **在场** | 非空仓根数占比 | **≥ θ₁** | **防躺平**（不交易 = 不达标） |
| **连续** | 最长连续空仓根数 | **≤ θ₂** | 防长期装死 |
| **平稳** | 最大回撤 | **≤ θ₃** | **防赌博式达标** |
| **节奏** | 换手率 | ∈ [θ₄, θ₅] | 下限防躺平、上限防乱枪 |

⇒ **「平稳交易下去」的可操作化 = 在场率下限 + 回撤上限 + 换手区间。**
这三条互相咬死：既不能靠不交易达标（在场），也不能靠豪赌达标（回撤）。

### 5.3 ⚠️ 但 KPI 有一个根本不确定性

**如果 KPI 只是写在 prompt 里，模型可能"说"要达标但不真的改变行为**
——这正是 `basis` 自报给我们的教训（自报"照指标"，实际与指标只有 36% 一致）。

⇒ 所以 KPI 的验证**一律从行为侧做，不看它说什么**：

| 问题 | 怎么测 |
|---|---|
| 落后目标时会不会**豪赌**？ | 落后组的**平均仓位** vs 达标组；杠杆/名义价值分布 |
| 落后目标时会不会**躺平**？ | 落后组的**弃权率时间序列**；最长连续空仓根数 |
| 达标后会不会**打卡**？ | 达标后 N 根的**交易率变化** |
| 有没有**提前冲刺**？ | 窗口末段的换手/仓位 vs 窗口前段 |

### 5.4 实验设计

**两组对照（同模板、同行情、同种子）**：
- **K 组**：prompt 里含目标声明 + 两条硬约束（在场率下限、回撤上限）
- **C 组**：同 prompt 但不含目标段（其余逐字节相同）

⇒ 主判据**不是收益**，而是 §5.3 那四个**行为指标**。
理由：KPI 改变的是**行为**，收益是行为的远端后果（而且噪声极大）。

⚠️ **一个必须先说清的设计风险**：KPI 数字本身**可能引导模型去赌**
（"要赚 5% 才达标" ⇒ 加杠杆）。这正是要加"回撤上限 + 在场率"的原因，
但**它是否真的奏效，必须实测**——不能假设写上去就有用。

## 6. ⑤ 工具效用的因果评估 —— "这工具是好工具还是坏工具"

### 6.1 三臂消融（用户那个问题的正面回答）

| 臂 | prompt 里给什么 | 检验什么 |
|---|---|---|
| **A 真指标** | 从当前 window 算出的指标 | （= v4） |
| **B 假指标** | ⚠️ **形状真实但无信息**的指标 | **"有指标这个形式"本身**的价值 |
| **C 无指标** | 同版面，删掉指标区块 | 基线 |

**三个差值各自回答一个问题**：

```
A − C = 工具的总效应（信息 + 引导）
B − C = 纯引导效应（有东西可看，但不含信息）
A − B = 指标的真实信息价值        ← 这才是"工具好不好"的答案
```

### 6.2 ⚠️ "假指标"怎么造才有效（这是设计里最容易做错的一步）

**不能用随机数**——随机数会与当前价格量级/方向明显矛盾，
模型会立刻发现"这数不对"从而弃权。那时测到的是"它会识破假数据"，
**不是**"它会盲信指标"。

⇒ **正确做法：用"错位时间"的真实指标**——形状真、量级真、但**与当前无关**：

```
把指标窗口整体往前挪 K 根（如 K=48）：
  给它的是 48 根之前的市场状态指标
  ⇒ 看起来完全正常，但对当前没有预测力
```

⚠️ 但仍有残余风险：**这些"过时指标"本身有自相关**，
所以它**不是完全无信息**（滞后 48 根的动量仍可能微弱相关）。
⇒ 报告里必须把这一点写明，并把 K 取足够大（如 2 倍窗口），
再**实测**"过时指标与当前收益的相关性"作为佐证。

### 6.3 验证

| # | 验证 | 判据 |
|---|---|---|
| V7 | 假指标确实"看起来正常" | 模型对 B 臂的**解析成功率**与 A 臂无显著差异（说明它没识破） |
| V8 | 假指标确实无信息 | 实测 `corr(假指标, 未来 h 根收益)` ≈ 0（附区间） |
| V9 | **工具好不好** | A − B 的**配对检验**（同段行情） |
| V10 | 引导效应有多大 | B − C；若 B > C 显著，说明**"给个东西看"本身就在改变行为** |

⭐ V10 很可能是最有趣的：**如果"假指标"也让它变好/变差，那说明我们测到的
从来不是"指标有用"，而是"给了它一根拐杖"。**

## 7. ⚠️ 前提工程：度量必须换掉（否则上面全部判不出来）

### 7.1 为什么必须换（实测）

A5 把样本从 120 根加到 **400 根（3.3 倍）**，结果
**8 个对照判定仍全是「依然无法判定」**，`required_n` 在 **5,000~55,000**。

原因：用"**每根平均收益率**"当度量时——
- 大部分根是"不交易"（收益恰为 0）⇒ 不提供信息；
- 带信息的那少数根**方差极大**；
⇒ 均值的置信区间宽到几乎包含一切。**加样本也追不上。**

### 7.2 换成什么：多段独立运行 + 同段配对

```
把 T 根切成 K 段（每段 L 根，K×L = T）
每段**独立起跑**（同初始权益、同 prompt、账户从零开始）
  ⇒ 得到 K 个**独立**观测（而不是 T 个强自相关观测）
每个观测 = 「这一段的总收益」
同一段上：LLM 跑一次、每条基线各跑一次  ⇒ **配对**
⇒ 对 K 个**配对差值**做检验（配对 t / 自助法）
```

**为什么效能高一个数量级**：K 个独立观测的有效样本量就是 K；
而"每根"那 T 个观测的有效样本量 ≈ T / (1 + 2Σρ) —— 在强自相关下远小于 T。

### 7.3 ⚠️ 段长与 K 的权衡（不能拍脑袋，要先做 power 分析）

- **L 太小**（如 20 根）：策略来不及表现，且每段的"策略差异"被开局噪声淹没；
- **L 太大**（如 200 根）：K 太少，检验效能不足。

⇒ **先用已有数据估**：段内自相关 ρ、段间方差 σ²，
反推"在给定 K 下能分辨的最小效应量"，再选 L。
**这一步不做，就是在猜。**

### 7.4 成本

⚠️ **不额外花额度**：`调用数 = 总根数 × 采样数`，与连续跑**完全一样**。
只是把"一次 400 根"改成"8 次 50 根"。
（基线是规则策略，免费。）

### 7.5 验证

| # | 验证 | 判据 |
|---|---|---|
| V11 | 段确实独立 | 段间收益的自相关 ≈ 0（附区间） |
| V12 | 配对确实配上了 | 同一段上 LLM 与基线读的是**逐字节相同**的行情切片 |
| V13 | 新度量真的更灵敏 | 用**已知的合成差异**（如故意给基线加成本倍数）测"能否判出来"，对比旧度量 |

⭐ V13 是**这套度量自身的验收**：如果一个度量连"人为制造的差异"都判不出来，
那它在真实比较里也判不出真差异。**先用合成差异标定灵敏度，再上真实验。**

### 7.6 ⭐ 已实测（2026-09-21，`tw/segmented.py`）

**度量已换，并且先做了灵敏度自检。** 结果如下（BTC-USDT-SWAP 1H，405 根）：

**① 灵敏度自检 —— 拿"成本 ×1 vs ×3"这个已知差异试**

| 度量 | 判据 | 结论 |
|---|---|---|
| **旧**（每根平均收益） | 400 根后 `required_n` **55,314** | ❌ 判不出来 |
| **新**（7 段 × 50 根配对） | 差值 `+0.3311%`，95% 区间 **[+0.2125%, +0.4497%]**，t=6.83 | ✅ **「×1 显著更高」** |

⇒ **新度量在 7 个观测上判出了旧度量要 5 万根才判得出的差异。**
且新度量在 n=7 时的**最小可分辨效应 = 0.136%**。

**② 段间相关 = `+0.083`（低，但**不是 0**）**

⇒ "段独立"这个假设**大致成立但不完全**。必须照实报：
相关为正时有效样本量 < K，检验偏乐观。
**本模块不声称独立，只把这个数报出来。**

**③ ⚠️ 但真实策略边际仍然难判 —— 这一条必须说清楚**

同一套新度量下，`momentum` vs `noop`（7 段）：

```
段间差值：+0.026% / −0.479% / −0.264% / −1.291% / +0.622% / +0.075% / +3.546%
均值 +0.319%   95% 区间 [−1.105%, +1.743%]   t = 0.55
⇒ 依然无法判定
```

**为什么同一个度量能判出成本、却判不出策略？**

| 差异类型 | 性质 | 可判性 |
|---|---|---|
| **成本** | 对**每一笔**都生效、方向确定 ⇒ **段间方差极小**（σ=0.128%） | 容易判 |
| **策略边际** | 依赖行情，**段间方差极大**（σ≈1.5%，单段从 −1.3% 到 +3.5%） | 难判 |

⇒ **诚实结论**：换度量**确实提升了灵敏度**（对一致性效应是数量级的提升），
但**它没有凭空造出可判定性**。要用它判 0.32% 的策略边际，
按 σ≈1.5% 反推 **约需 180 段（≈9,000 根）**。

**⇒ 所以"不接受无法判定"这条要求，需要先回答一个更基本的问题：**

> **我们想判的效应，到底有多大？**

如果策略的真实边际就是 0.3% 量级，那**任何**度量都需要近万根。
⇒ 三条路（见 §11 待拍板第 7 条）：
1. 接受"要用万根级样本"这个成本；
2. **放大效应**：换更长的持有期、更低的成本假设、或更极端的行情段；
3. **换问题**：不问"收益差异"，改问 §5.3 那些**行为指标**
   （仓位/弃权/连续性）——它们段间方差通常小得多，**更容易判**。

⭐ 第 3 条与 §5 的设计正好接上：**KPI 的效果本来就不该用收益去验。**

### 7.7 ⚠️ 施工中撞上的三个真缺陷（都在这套度量自己身上）

**① σ=0 时判"无法判定" —— 把结论弄反了（最典型）**

配对差值**完全一致**（σ=0）时，朴素的 `se = s/√n if s > 0 else nan`
会给出 `se = nan` ⇒ 区间 `(nan, nan)` ⇒
`nan > 0` 与 `nan < 0` **都是 False** ⇒ 落进「依然无法判定」。

**方向正好相反**：一致性最强（完美一致的效应）的时候说"判不出来"。
而**成本倍数这类确定性效应正是在 σ≈0 时被观测到的**
——本轮的自检就撞上了这个情形。

- 修法：σ=0 时区间**塌成一点**（`lo = hi = m`），`t = ±inf`。
- 修法后：完美一致(正)→「显著更高」、完美一致(零)→「无法判定」。
- 守卫：M97（拆掉这个分支后首挂 `test_t值方向正确`）。

**② M98 第一次**漏网**，暴露了一个真测试缺口**

M98 第一版写成了"**同段内各配置共用一个账户**"（我把账户提到了**配置**循环外，
而不是**段**循环外）。它**没有被抓住**——因为我只检查了
"跨段是否新建账户"，**没检查"同段内不同配置是否各用各的"**。

后者同样致命：共账户时**配对就配错了**（B 的成绩里混进了 A 的盈亏）。

⇒ 补了 `test_同一段内各配置的账户也彼此独立`
（用 `momentum` + `noop`：共账户时 `noop` 不再是 0），
并把两条**分开编号**：M98 = 跨段共享、M100 = 同段跨配置共享。

> **可复用判据**：写下"每段必须新建账户"时，要问**"还有谁会共用它？"**
> ——"每个 X 一个独立实例"的说法里，X 可能有两层（段、配置），
> 而**只守一层是防不住的**。

**③ 一个测试第一版没有分辨力**

`test_小样本用t临界而不是1_96` 第一版挑的样本**用正确临界值也算显著**
⇒ 它**区分不出**"用 1.96"与"用 t 临界值"。
⇒ 重新挑了一组 `1.96 < t < t_crit` 的样本，并显式断言
"用 1.96 会判显著"。**断言存在 ≠ 有分辨力**（本项目第三次踩）。

## 9. 诚实边界（必须先说清楚）

1. **复盘/经验很可能看不出效果。** 这个领域公认——"LLM 能总结宏观，
   却是个糟糕的仓位引擎"。所以 V5 的主判据刻意选**行为**而不是收益。
2. **KPI 可能被"说一套做一套"。** 这正是 `basis` 自报给我们的教训
   （自报"照指标"，实际与指标只有 36% 一致）。⇒ 一律从行为侧验证。
3. **"假指标"不能做到完全无信息**（错位指标仍有自相关）。
   ⇒ 必须实测并报告相关性，不能声称"零信息"。
4. **三臂消融的成本高**（三倍调用）。可能先只做 A vs C（已有），
   把 B 臂留到"A−C 出现信号"之后再补。
5. **本方案不含"真钱"（B 路线）的任何内容。**
6. **"平稳交易下去"是好要求，但它的量化阈值（θ₁~θ₅）目前是拍的**，
   需要先用**基线的行为分布**标定——基线是怎么"平稳"的，就照那个量级设。
