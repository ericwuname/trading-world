交易世界实例化：基于主体建模(ABM)施工蓝图
项目目标与边界（先读这一段，决定了后面所有设计取舍）
目标：构建一个最小化的人工市场，让简单的agent互相交互，检验能否涌现出真实加密市场的统计特征（肥尾分布、波动率聚集、你在之前分析里发现的"扫单后继续走而非反转"等现象）。

明确不是目标：

不是为了预测下一个价格
不是为了直接产出可交易信号
是为了理解"这些现象的最简生成机制是什么"
成功标准：模拟输出的价格序列，统计特征应该在数量级上逼近真实BTC数据（你之前跑过的分析里已经有现成的对照基准），而不是要求逐笔价格吻合。

第一部分：理论基础（agent要遵循的设计原则）
参考两个经典实验，作为MVP阶段的设计蓝本：

Gode & Sunder (1993) 零智能交易者：证明市场机制本身（连续双向拍卖）就能让价格收敛到接近均衡，不需要聪明的agent。第一阶段先实现这个，作为对照基线。
Lux & Marchesi 图表派-基本面派模型：只用两类极简单agent的交互，涌现出肥尾和波动率聚集。第二阶段在零智能基线上叠加这两类agent。

第三部分：详细规格
3.1 Order 数据结构
@dataclass
class Order:
    agent_id: str
    side: str          # 'buy' or 'sell'
    price: float
    quantity: float
    timestamp: int      # tick序号，用于时间优先撮合
    order_id: str
3.2 OrderBook
买单队列：按价格降序排列（最高买价在前）
卖单队列：按价格升序排列（最低卖价在前）
同价格内部按时间优先排列
提供方法：add_order(), cancel_order(), get_best_bid(), get_best_ask(), get_mid_price()
3.3 MatchingEngine（连续双向拍卖逻辑）
每次新订单进来时：

若是买单，检查是否 price >= best_ask，是则成交（价格取先挂单方的价格，即被动方价格优先），成交量取双方剩余量的较小值
若未完全成交，剩余部分挂入订单簿
若是卖单，逻辑对称
每笔成交记录进 TradeLog：(tick, price, quantity, buy_agent_id, sell_agent_id)

3.5 各类Agent的具体决策逻辑
A. ZeroIntelligence（零智能交易者，第一阶段核心）
每个tick以概率 p_active（如0.1）决定是否下单
随机选择买/卖方向（各50%概率）
报价：在当前中间价 ± 一个随机幅度内均匀采样（幅度可设为中间价的0.1%~2%）
数量：从某个分布（如指数分布）随机采样
约束：不能卖空超过自己持仓，不能买超过自己现金能承受的量（简单的预算约束）
B. Fundamentalist（基本面派）
假设一个外生的"基本面价值" V(t)（可以设为一个缓慢随机游走，或者干脆用真实历史数据的价格趋势线作为代理）
若当前价格 P(t) < V(t)：买入，力度正比于 (V(t)-P(t))/V(t)
若当前价格 P(t) > V(t)：卖出，力度同理
这类agent天然带来均值回归压力
C. Chartist / Trend Follower（图表派）
观察过去N期价格的动量：mom = (P(t) - P(t-N)) / P(t-N)
若 mom > 0：买入（追涨）；若 mom < 0：卖出（杀跌）
力度可以正比于动量强度，也可以设一个阈值触发
这类agent天然带来趋势强化压力（这正是Lux-Marchesi模型里涌现肥尾的关键来源——正反馈循环）
D. MarketMaker（做市商，可选，第三阶段加）
同时挂买单和卖单，价差(spread)固定或根据近期波动率动态调整
库存风险控制：库存过多时主动调整报价引导库存回归中性
这类agent提供流动性，抑制极端波动
第四部分：分阶段施工计划
阶段1：MVP——纯零智能基线（对应Gode-Sunder实验）
只实现 ZeroIntelligence agent，比如200个
跑10000个tick，画出价格序列
验证标准：价格是否围绕某个水平震荡收敛（不发散、不崩溃），订单簿深度是否稳定
阶段2：加入基本面派+图表派（对应Lux-Marchesi）
保留部分零智能agent作为"噪音底噪"（如30%）
加入40%的Fundamentalist、30%的Chartist
验证标准（关键指标，逐一和真实BTC小时线数据对照）：
收益率分布的峰度(kurtosis)：真实市场应远大于3（正态分布的峰度），检查模拟数据是否也显著大于3（肥尾）
波动率聚集：计算 |returns| 的自相关函数，真实市场在多个滞后期上应显著为正；检查模拟数据是否也呈现这个模式
收益率本身的自相关：真实市场里returns自身几乎没有自相关（弱有效市场），但|returns|有——检查模拟数据是否也符合这个不对称
参考你之前的动量/反转测试结果作为额外校准目标（如果调整Chartist和Fundamentalist的比例，模拟数据能不能重现"扫单后继续走"这类现象）
阶段3：加入做市商，测试极端行情下的脆弱性
加入MarketMaker agent
做一次"压力测试"：让某个agent群体的仓位突然被强制平仓（模拟清算），观察价格冲击如何在订单簿中传导、恢复需要多久
这一步直接对应你之前提的"清算流动性捕获"假设——用模拟环境去理解这个机制的生成原理，而不是在真实数据里盲测
阶段4（探索性，非必须）：参数校准与敏感性分析
用你已有的真实BTC/BNB/BCH数据的统计特征作为目标，网格搜索agent比例、报价幅度等参数，让模拟输出尽可能逼近真实统计特征
注意：这一步的目的是"理解哪些参数组合能产生真实市场的模式"，不是"校准出一个用来预测的模型"——警惕把这一步异化成又一轮参数过拟合
第五部分：技术实现建议
语言：Python，用 dataclasses 定义Order，heapq或sortedcontainers.SortedList实现高效的订单簿（避免每次插入都全量排序）
性能：如果agent数量或tick数增大导致慢，可以用 numpy 向量化agent的决策计算（比如所有ZeroIntelligence agent的随机决策可以批量生成）
可视化：用 matplotlib画价格时间序列、订单簿深度热力图；用 scipy.stats 算峰度、自相关
对照数据：直接复用你之前上传的BTC/BNB/BCH的CSV，在Analyzer阶段计算同样的统计量做对比
第六部分：给执行agent的具体任务分解（可以直接作为任务清单丢给本地coding agent）
搭建 Order、OrderBook、MatchingEngine 三个核心类，写单元测试验证撮合逻辑正确（比如：买价>=卖价时应该成交，价格应取被动方价格）
实现 ZeroIntelligence agent，跑阶段1的MVP，输出价格时间序列图
实现 Fundamentalist 和 Chartist，跑阶段2，实现 Analyzer 计算峰度、波动率聚集的自相关函数
写一个脚本，加载真实BTC小时线CSV，计算同样的统计量，跟模拟结果并排输出对比表格
（可选）实现 MarketMaker，跑阶段3的压力测试场景
需要提前认清的边界（避免中途产生不切实际的期待）
这个模拟器不会告诉你"下一步该买还是该卖"
即使模拟成功重现了真实市场的统计特征，也不代表你能从中提取出一个可交易的信号——这是两个不同难度的问题（我们之前聊过的反身性问题在这里依然成立）
这个项目的产出是理解力：知道"肥尾从哪来"、"波动率聚集的最小生成条件是什么"、"清算连锁反应的传导机制长什么样"——这些理解可能间接帮助你更好地设计风控（比如更准确地估计尾部风险），但不会直接给你一个edge
