# 交易终端 · 设计方案（TradingView 式）

> 目标：在**本项目自己模拟出来的市场**上，做一个"能一根一根走过去、能在图上下单、
> 能看见盘口怎么被吃掉"的图表终端。
>
> 状态：**进行中**。本文档是长程任务的唯一进度依据（上下文会丢，文件不会）。

## 1. 范围：我做什��，我不做什么

### 做（且能做完、能验证）

| 能力 | 验收判据 |
|---|---|
| K 线图 + 成交量 | 从 `SimLog` 逐 tick 聚合出 OHLCV，与逐 tick mid 对得上 |
| 十字光标 + OHLC 浮窗 | 鼠标移动显示那一根的 OHLCV 与时间 |
| 缩放 / 平移 / 复位 | 滚轮缩放、拖拽平移、双击复位，坐标轴跟随 |
| 时间周期聚合 | 由 tick 聚合出 1/4/16/64 根一根的 K 线 |
| 盘口深度阶梯（DOM） | 逐档买卖量 + 价差，点击档位可下单 |
| **逐根回放** | 播放 / 暂停 / 单根前进 / 速度，状态可复现（固定种子） |
| **纸上交易** | 从图上下单 → 走**真实撮合引擎** → 成交/撤单回填、持仓与余额 |
| 指标 | σ、成交量、深度、主动买卖差（**都是这个市场自己的量，不是 TA 指标**） |
| 绘图工具 | 趋势线、水平线、矩形（少量够用，可持久化） |

### 不做（明确拒绝，写下来免得日后滑进去）

- ❌ **不做 Pine Script** —— 那是 TradingView 的语言，接进来就等于寄生。
- ❌ **不追求 TradingView 功能对等**（110+ 绘图工具、100+ 指标、13 种图型）——
  那是多年多团队的产品。**对等是伪目标，���用是��目标。**
- ❌ **不引第三方图表库** —— 见 §2。

## 2. 许可与依赖：为什么自己手写 canvas

查过（2026-10-04），三条路都走不通或不该走：

| 方案 | 许可事实 | 结论 |
|---|---|---|
| TradingView **Advanced Charts / Trading Platform** | 官方明确"**不提供**用于个人、研究、测试"；仅限公司公开网页项目；源码不提供 | ❌ 许可不允许 |
| TradingView **Widget**（iframe 复制粘贴） | 数据是 **TradingView 自己的** | ❌ 我们要的是自己模拟的市场 |
| **Lightweight Charts™** | Apache 2.0、**可个人使用** | ⚠️ 合法，但违背本项目"零额外依赖 / 零构建步骤 / 不引第三方库"（`gui/static/index.html` 里已写着这条纪律） |

⇒ **决定：图表内核手写 canvas。** 理由不是偏好，是**许可 + 项目底线**两条同时成立。
顺带好处：本项目没有构建步骤，手写 canvas 的图**离线可用、打包后体积不涨**。

### ⚠️ 2026-10-05 修订：决定**推翻**，改用 Lightweight Charts™

**为什么推翻自己**：用户反馈"输出结果太粗糙"。复盘后诊断出的根因之一是——
**我在手搓一个已被解决的问题**（平移/缩放/十字光标/坐标轴自适应/多周期/标记点），
搓出来还不如现成的。工程量应该花在**真正属于本项目**的地方：
回放、盘口、纸上交易、成交标记。

**许可核查**（同一个 Apache 2.0 库，TradingView 官方开源那一档）：

| 约束 | 状态 |
|---|---|
| 引第三方代码 | ❌ **破了**（唯一被打破的一条，明确记录在此） |
| 零构建步骤 | ✅ 保持 —— 一个本地 `<script src="/static/vendor/…">`，不是打包器 |
| 完全离线 | ✅ 保持 —— **本地文件，不是 CDN**，断网可用 |
| 不加载任何外部资源 | ✅ 保持 —— `tests` 里有专门一条断言在盯 |

**文件位置**：`gui/static/vendor/lightweight-charts.standalone.production.js`（177 KB）
⚠️ 静态路由**只认 `/static/` 前缀**（`server._dispatch` 里写死的）⇒ 写成 `vendor/…` 会 **404**
⇒ 页面仍"正常"、只是图不出来 ⇒ 已写成一条测试（`TestVendoredChartLib`）。

**API 迁移的坑**：v5 **改了标记 API** —— 不再是 `series.setMarkers()`，
而是 `createSeriesMarkers(series, data)` 返回独立 primitive。
按 v4 写法调 ⇒ `is not a function`，而它挂在重绘主链上 ⇒ **整个右半边全废**。
⇒ 现在两种 API 都试，且整段包 `try/catch`（标记是锦上添花，不许连累 K 线）。

## 4. 架构

```
浏览器（单文件 HTML，零构建）
  │  fetch /api/terminal/*（带 X-TW-Token）
  ▼
gui/terminal.py          ← 新增：会话管理层
  · TerminalSession      一个"能一根一根走"的市场 + 一个纸上账户
  · 线程锁（HTTP 服务器是多线程的，会话状态必须加锁）
  ▼
tw.market.Market         ← 已有，不改
  · step() / submit() / cancel() / snapshot()
```

ⓘ **会话归属**：一个进程一个默认会话（本地单用户工具）。
ⓘ **可复现**：会话用固定种子；同样的操作序列 ⇒ 同样的结果（这是本项目的强项，
   TradingView 的回放给不了这个）。

### S1/S2 的实测结论（不是"写完了"）

- 建会话（预热 4000 tick）**3.2 秒**；`step(200)` 走完 tick 4000 → 4200；
  K 线 200 根、OHLC 自洽、`close` 与该 tick 的 mid **精确相等**；
  盘口买卖各 12 档、价差 101.11、mid 居中；
- ⭐ **纸上订单真的走撮合引擎**：低于卖一的限价单挂上（0 成交），
  穿价单立刻成交（58,981.09），库存/现金/成交明细/撤单全对；
- ⭐ **可复现**：同种子两个会话 200 根 close 逐点相同。

### S1 顺手修掉的一个真问题

纸上账户原本写死 10 万现金，在 normal 场景（价格 ≈ 5.9 万）**只买得起 0.47 手**
⇒ 开箱即用极难受。改成 `cash=None` 时**按 `初始价格 × 200` 自动定**（1200 万）。
**教训**：终端类界面的默认值必须**跟着领域的尺度走**，不是跟着"看起来合理"走。

## 6. 这个终端为什么值得做

不是为了"像 TradingView"，而是因为**它是把 ABM 变成"看得懂的东西"的最后一步**：

- 现在的 GUI 给你的是**结果数字**（年化、偏度、胜率）；终端给你的是**过程**。
- ⭐ **逐根回放 + 盘口阶梯**能让人亲眼看到：
  「一次 2% 的清算怎么把盘口打空」—— 这是本项目最贵的那条结论
  （冲击 10.5 倍、成交率 100%→4%），**文字讲一天不如自己走一遍**。
- 而且它天然回答了"深度来自时间"这条结论：**自己拆 1 片和拆 100 片，
  在图上点两下就看见了。**
