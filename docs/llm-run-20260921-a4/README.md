# A4 LLM 分层评估证据（2026-09-21）

> 与 A3 的 `docs/llm-run-20260921/` 同源：**报告里的数字必须能追溯回某次运行。**
> 本次的核心结论是**一个否定结论**（LLM 打不过基线），
> 那更需要原始证据——"没赢"这件事最容易被怀疑是"跑错了"。

## 文件

| 文件 | 内容 | 为什么留它 |
|---|---|---|
| `rec_BTC.jsonl.gz` / `rec_ETH.jsonl.gz` | **LLM 原始响应**（各 360 次调用） | **不可再生**（花过钱）——能查"模型当时到底说了什么" |
| `dec_BTC.jsonl.gz` / `dec_ETH.jsonl.gz` | **决策留痕**（各 120 条，证据链六项） | 能查"建议 → 风控 → 订单 → 成交"每一步 |
| `eval_BTC.json` / `eval_ETH.json` | 分层评估结果（报告的唯一输入） | 报告的每个数字都从它现算 |
| `relog_*.txt` | 评估运行的原始输出 | 人工可读的对照 |

⚠️ `dec_*.jsonl.gz` 可由 `rec_*.jsonl.gz` **回放重建**（成本 ×1 时回放覆盖率 100%），
但 `rec_*.jsonl.gz` **不能**由 `dec_*` 重建——所以前者更重要。

⚠️ `.gz` 只是为省体积（压缩比约 4%）。`ReplayClient` 直接支持 `.gz`。

## 安全说明

**无密钥、无认证头。** 已用
`grep -l "cpk-\|Bearer\|Authorization\|sk-proj"` 扫过，零命中。

录制文件只含：`prompt_hash` / `messages` / `model` / `temperature` /

## 怎么复核

```bash
# 1) 看模型当时看到了什么（离线）
python scripts/agent_cli.py --inst BTC-USDT-SWAP --n 1 --template v2 --show-prompt

# 2) 从归档回放，重建决策与评估（离线，零 API 成本）
python scripts/agent_eval.py --inst BTC-USDT-SWAP --n 120 --samples 3 \
    --template v2 --replay docs/llm-run-20260921-a4/rec_BTC.jsonl.gz \
    --out-json /tmp/eval.json

# 3) 重生成报告（数字全部现算）
python scripts/make_a4_report.py
```

⚠️ **回放只能在成本 ×1 时复现真机。** 换成本（×2/×5）会让回放覆盖率
从 100% 掉到 0.8%——因为 prompt 含账户状态、而账户状态取决于成交路径。
详见 `docs/A4-分层评估报告.md` §5 与设计方案 §7.8。

## ⚠️ 已知边界（不要过度解读）

1. **样本很小**：每格 120 根、27 笔左右的交易。所有与基线的比较
   **都是「依然无法判定」**（区间重叠 38%~70%）。这**不是**"没有差别"，
   而是"用这个样本量分不出来"。报告里给了 `required_n`。
2. **单一市场区间**：120 根取自同一段行情（BTC/ETH 同期）。
   换一段行情结论可能不同。跨 5 场景 × 多种子的稳健性检验**尚未做**。
3. **未模拟资金费率**：真实 OHLCV 库里没有费率数据 ⇒ 费率按 0 计。
   永续多头在正费率环境下会持续付费，本报告**没有体现这部分成本**。
4. **bar 级成交的四个假设**见 `docs/A4-分层评估报告.md` 与 `tw/simexec.py` 顶部。
   其中"限价单碰到即成交"**偏乐观**、"同根 TP+SL 双触发按 SL"**偏悲观**。
