## 1. 前置校验三步

任务书 §2.2 要求比对两份产物（`out/workstream_A/EA4_config.json` 与 `EA4_lambda_calibration_config.json`）。**这两份文件不存在**——EA.4 的配置一直是 `scripts/run_workstream_A.py` 里的常量，λ̄ 是运行时算的。

更关键的是：**比对两份手抄配置本身并不能满足第六条纪律**——两份 JSON 也可以「看起来一样、实际不同步」。所以改成三步（见 `scripts/verify_EA4_calibration.py`）：

| 步骤 | 检查什么 | 结果 |
|---|---|---|
| ① 来源核对 | 实验侧**实际生效**的配置（`run_stage3.make_market` 内部写死的 `N_AGENTS`/`MM_KW`） vs 标定侧**实际收到**的 kwargs | ✅ 一致 |
| ② 物化核对 | 两侧各自真实构造一个市场，比对主体构成指纹（防「参数一样但构造路径不同」） | ✅ 一致（{'chartist': 81, 'fundamentalist': 108, 'market_maker': 30, 'zero_intel': 81}） |
| ③ 窗口核对 | 标定窗口是否等于实验窗口 | ❌ **不一致** |

- window: 标定侧=[500, 3000] ≠ 实验侧=[6000, 6400]

**①② 是干净的**：EA.4 当年就传了 `sim_kw=MM_KW`，所以它**没有**踩 E8.2 那种「裸市场标定、带做市配置使用」的坑。
（②的指纹一致也说明：`make_market` 内部写死的常量与 spec 没有脱节。）

**③ 不一致——这是一个真实缺陷，且是本轮才发现的一类**：
标定用 `[500, 3000)`（含前 500 tick 瞬态），实验跑在 `[6000, 6400]`。两者相差约 7%，会让 λ̄ 偏高（旧口径 94.601 vs 同窗口的 91.692）。

## 6. 要把分辨力做到可用，需要多少种子？

区间宽度 ∝ 1/√n（标准误的定义），以现行 4 档 + 3 种子为基准外推：

| 要做到 | 约需种子数 | 成本判断 |
|---|---|---|
| 分辨 0.455 vs 1.042（差 0.587） | 35 | 便宜 |
| 分辨 0.947 vs 0.455（差 0.492） | 50 | 便宜 |
| 判定是否落在 0.5±0.1 | 300 | 昂贵（需换指标或增加档位） |
| 判定是否落在 0.5±0.05 | 1200 | 昂贵（需换指标或增加档位） |
| 判定是否落在 0.5±0.02 | 7499 | 昂贵（需换指标或增加档位） |

⚠️ 这是**下界式**估计：它只考虑「加种子」这一条降噪途径。另外两条是：

1. **增加冲击档位**——现在只用了 4 档（0.1% / 0.25% / 0.5% / 1%），而 `run_stage3.SHOCK_SIZES` 里有 **7 档**（到 2% / 4% / 8%）。OLS 用更多点会显著降噪，但大档位会因 `fill_ratio < 0.95` 被 `unsaturated()` 剔除，所以要先看饱和从哪一档开始。
2. **提高信噪比**——现有 4 档里低档位几乎全是噪声（t < 1.6），而信号在大档位清晰（1% 档 t = −4.93）。也就是说：**同一批预算下，把种子投在大档位上比平均撒更划算。**

⚠️ 最要紧的一条：**判定「是否落在 0.5±0.1」需要约 300 个种子。**而任务书整轮的目标（D/E/F 各线「逼近 0.5」）都建立在这个判定上。在补足分辨力之前，**即使跑完 D/E/F，也无法回答「有没有更接近 0.5」**。
