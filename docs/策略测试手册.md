# 策略测试手册

> 这份手册回答一个问题：**我写了一个交易策略，怎么用这个人工市场检验它？**
>
> 相关文件：`tw/strategy.py`（API）、`tw/eval.py`（指标）、`tw/scenarios.py`（场景）、
> `scripts/lab.py`（批量实验台）、`strategies/`（示例与模板）。

---

## 0. 先说清楚：这个环境能检验什么，不能检验什么

**能**：

- 策略在**响应式**环境里的表现——你的单会改变盘口，别人会对你反应。
  这是历史回测做不到的（回测里市场对你是死的）。
- 策略在**极端状态**下的表现——高波动、清算冲击、流动性枯竭。
  这些在历史数据里样本太少，或根本没有。
- **成交质量**的归因——你赚的是价差，还是承受了逆向选择？
  在真实数据里这个问题很难回答，因为你看不到别人的订单流。
- **稳健性**——同一策略在五个场景下的表现差异。

**不能**：

- 预测未来收益。模拟里的"真实价格"是内生的，没有外部真值。
- 直接外推到真实市场。模型的微观结构（深度剖面、清算机制）与真实有明确差距，
  第 11 节列了。**在这个环境里赚钱不等于在真实市场赚钱。**
- 替代历史回测。两者的偏差方向不同，应当**互补使用**：
  回测告诉你"在历史上会怎样"，这里告诉你"在机制变化时会怎样"。

## 2. 写一个策略

新建 `my_strat.py`：

```python
from tw.strategy import Strategy

class MyMaker(Strategy):
    """最简单的一版做市：在中间价两侧挂固定价差。"""

    def __init__(self, *args, half_spread_bp=12.0, qty=2.0, **kw):
        super().__init__(*args, **kw)
        self.half = half_spread_bp
        self.qty = qty

    def on_tick(self, ctx):
        mid = ctx.mid
        if mid is None:
            return None
        ctx.cancel_all()                       # 每 tick 撤旧挂新
        bid = mid * (1 - self.half / 1e4)
        ask = mid * (1 + self.half / 1e4)
        return ctx.quote(bid, ask, self.qty)   # 双边挂单
```

跑它：

```bash
python scripts/lab.py --strategies my_strat:MyMaker --scenarios normal,stressed
```

### 可用的钩子

| 钩子 | 何时调用 | 用途 |
|---|---|---|
| `on_start(ctx)` | 第一次决策前一次 | 参数校验、建缓冲区 |
| `on_tick(ctx)` | 每个 tick | **主决策**，返回 `None` / 一个订单 / 一组订单 |
| `on_fill(fill)` | 自己的订单成交时 | 推进执行进度、统计成交质量 |
| `on_end(ctx)` | 模拟结束时一次 | 收尾计算 |

### `ctx` 里有什么

```python
# 行情
ctx.tick, ctx.mid, ctx.best_bid, ctx.best_ask
ctx.spread, ctx.spread_bp            # 绝对价差 / bp
ctx.fundamental                      # 基本面锚（模型内生的"真值"）
ctx.mid_lag(n), ctx.momentum(n)      # 历史中间价、动量
ctx.mid_std(n)                       # 近期波动幅度（bp），做市调价差用

# 账户
ctx.cash, ctx.inventory
ctx.available_cash, ctx.available_inventory   # 扣除已挂单预留后的可用额度
ctx.open_orders, ctx.n_open_orders
ctx.equity(), ctx.pnl()

# 下单（全部走预留制记账 + tick 网格吸附）
ctx.buy(price, qty) / ctx.sell(price, qty)
ctx.market_buy(qty) / ctx.market_sell(qty)
ctx.limit_at(side, offset_bp, qty)            # 中间价 ± offset_bp
ctx.quote(bid, ask, qty)                      # 双边，返回实际生效的订单列表
ctx.cancel_all()
```

### 三条约束（都是设计上刻意的）

1. **下单会自动裁剪到可用额度**。想下 1000 手但只买得起 2 手 → 实际下 2 手。
   不是拒单——拒单会让策略在资金紧张时完全停摆，而真相是"它能做小一点"。
2. **挂单受 `max_open_orders` 与 `order_ttl` 约束**。超量会被撤最早的、
   超时会被自动撤。
3. **抛异常不会带崩模拟**，但会被计数并汇总到结果里
   （`n_errors` / `first_error`）。**不要忽略这两个字段**——
   策略写错了却"什么都没做"，看起来会像"策略判断不该交易"。

## 3. 怎么读结果

### 3.1 两个必须有对照系

实验台每次都自动带上 `noop`（什么都不做）。**它是口径基准，不是凑数的**：

- `noop` 必须**恰好 0 成交、0 盈亏**。不为 0 → 评估代码有 bug，先修它。
- `noop` 也是健全性检查：注入它之后背景行情必须与不注入时**逐点相同**
  （`--integrity` 会实测）。不成立的话，整张表里所有差异都混着
  "多了一个主体"这个伪影。

### 3.2 核心指标：Markout（成交质量）

对每笔成交，设 `s = +1`（买）或 `−1`（卖），`m` = 成交当时的中间价：

| 指标 | 公式 | 读法 |
|---|---|---|
| **价差捕获** `capture` | `s·(m − price)/m·1e4` | 成交瞬间相对中间价的优势。**被动挂单为正**（赚了价差），主动吃单为负 |
| **漂移** `drift(h)` | `s·(mid[t+h] − m)/m·1e4` | 成交后 h tick 价格朝哪走。**负值 = 逆向选择**（接了有毒的单） |
| **实现** `realized(h)` | `capture + drift(h)` | 每单位成交的**实际**盈亏 |

**判读纪律**：只看均值会在噪声上编故事。必须看 `h20的t` 那一列，
`|t| < 2` 就是噪声，不能解读。

一个典型结果（本项目实测，做市策略）：

| 策略 | 价差捕获 | 漂移 h20 (t) | 实现 h20 | 解读 |
|---|---|---|---|---|
| 朴素做市 | +5.6bp | −9.9 (−7.9) | **−4.2bp** | 账面上赚了价差，但每笔成交平均是**净亏**的；它的 PnL 来自行情不是做市 |
| 加库存偏移 | +5.3bp | −16.6 (−12.5) | −11.2bp | 逆向选择**更严重** |
| 随机吃单 | −30.1bp | −24.7 (−2.1) | −54.8bp | 付价差 + 轻微逆向选择 = 无信息者的必然结局 |

### 3.3 PnL 三分解：钱从哪来

```
pnl_total = pnl_capture + pnl_inventory + pnl_initial_mark
              价差捕获        库存期间价格变动    底仓被重新估值
```

这个恒等式**精确成立**（有测试保证），所以"钱从哪来"没有含糊空间：

- **`pnl_capture`** 才代表策略的本事。
- **`pnl_inventory`** 是持仓期间行情给的——做市商应该尽量让它小。
- **`pnl_initial_mark`** 是初始底仓的估值变化。**一个完全不交易的账户
  也会有这一项。** 很多人把这一项当成策略收益，这是最常见的自我欺骗。

本项目实测过一个典型例子：TWAP 执行策略的 PnL 是 +149,831，
其中 `pnl_capture` 只有 **−1,699**（执行本身是微微亏的），
剩下 151,530 全部来自 `pnl_inventory`——就是"建仓期间市场涨了"。

### 3.4 风险与库存

| 指标 | 用途 |
|---|---|
| `max_dd` / `max_dd_pct` | 最大回撤。**没有回撤的收益曲线不存在**，只看收益不看回撤等于没测 |
| `sharpe_per_tick` | 逐 tick 的单位风险收益。**不做年化**——年化要先约定 1 tick = 多久，本项目的"1 tick ≈ 1 小时"只是刻度不是真实时序 |
| `inv_abs_mean` / `inv_abs_max` | 库存规模。做市商赚不赚钱常常取决于库存管不管得住 |
| `flat_frac` | 贴平时长占比 |
| `maker_volume_frac` | 被动成交占比。做市类策略的结构指标；若接近 0，那它根本不是在做市 |

**风险与收益必须一起看。** 本项目实测到一个清晰的例子：
给做市策略加上"库存偏移"之后，库存均值从 7.63 降到 0.58、
最大回撤从 −241k 压到 −32k（**7 倍改善**），但 PnL 从 +103k 变成 **−12k**。
两个数字单看都像"出问题了"，一起看才是"用收益换风险"的取舍。

### 3.5 标准误

`±标准误` 是跨种子算的。**任何"优于基准"的结论都必须在标准误之外。**
只跑一个种子挑最好看的结果，是把噪声当信号。

## 4. 五个场景：为什么要跨场景跑

单场景评测是策略研究里最经典的自我欺骗：调参直到在默认参数下好看，
然后宣布"策略有效"。真实市场不会一直待在默认参数里。

| 场景 | 它测什么 |
|---|---|
| `normal` | 基准配置。**所有策略必须先在这里站住**，再看其他场景 |
| `calm` | 流动性稀薄但波动温和 → 测"红利消失后的下限" |
| `stressed` | 高波动、图表派正反馈主导 → 测回撤、库存失控、会不会越亏越加仓 |
| `liquidation` | 承压之上再加一次强制平仓 → 测"别人爆仓时你会怎样" |
| `thin` | 主体数减到 1/4 → 测流动性依赖度：在厚市场里的表现有多少来自"盘口托住了它" |

**一个只在 `normal` 场景赚钱的策略不是策略，是一个巧合。**

## 5. 一个完整的分析流程（建议照做）

1. **先跑 `noop` 与 `random_taker`**。确认基准正常、确认"无信息就是亏"。
   如果你的"聪明策略"和随机吃单没有统计差异，那它就是随机吃单，
   不管内部逻辑看起来多复杂。
2. **在 `normal` 上跑多个种子**（默认 4 个）。看 `pnl_capture` 与 `realized_20bp`：
   - 两个都显著为正 → 真有本事
   - `capture` 正但 `realized` 不正 → 在赚价差，但同时在被逆向选择挑走
   - 两个都 ≈ 0 → 它在做无用功（先检查 `n_fills`，可能压根没成交）
3. **看 `h20的t`**。如果漂移不显著，说明策略没有方向性信息；
   如果显著为负，说明它的成交是有毒的。
4. **跨五个场景重跑**。记录 PnL 与 `max_dd` 在场景间的跨度。
   跨度大的策略不可信——它的表现更多取决于市场状态，而不是它自己。
5. **只在这之后**才去看"怎么调参让它更好"。
   先确认它在做什么，再优化它怎么做。

## 6. 常见陷阱

| 陷阱 | 症状 | 对策 |
|---|---|---|
| **把底仓重估当收益** | `pnl_initial_mark` 很大、`pnl_capture` ≈ 0 | 先看分解再看合计 |
| **只看均值不看 t 值** | 报出一个小数点后两位的"改进" | `|t| < 2` 一律当噪声 |
| **单种子挑好看结果** | 换种子结论就变 | 默认 4 种子 + 标准误 |
| **只跑 `normal`** | 换个场景就崩 | 五个场景是默认动作 |
| **策略静默失效** | `n_fills = 0` 或 `n_errors > 0` | 结果里这两个字段必须先看 |
| **把"没成交"读成"策略克制"** | `n_fills` 很低但没报警 | 检查 `ctx.available_cash`——可能是订单被裁剪成 0 |
| **在 `stressed` 里越亏越加仓** | 最大回撤远超 PnL 量级 | 加库存上限；对比 `mm_naive` 与 `mm_skewed` |

## 7. 复现性：三条必须遵守的规则

本市场做过专门设计以保证"策略 A/B 对比"成立。这三条破坏任何一条，
结果都会照跑不误、只是**不再可比**：

1. **必须用 `market.add_agent(strategy)` 注入**，不能 `market.agents.append()`。
   后者不进 `by_id`，结算时找不到对手方账户。
2. **必须记录注入时点**（`market.injected_at`）。同一 seed 只有在
   注入时点也相同时才复现得出同一场实验。
3. **不要在预热期注入策略**。项目约定：`Scenario.build(seed)` 跑完预热 →
   注入策略 → 再观测。让策略参与预热会让各策略把市场带到不同状态，
   后面的对比就不再是"同一初始条件下的差异"。

底层保证（已固化为测试）：

- **主体数量与背景行情解耦**。市场随机流只用于基本面步进；
  禀赋来自每主体独立的流；动作顺序由每主体独立的优先级决定。
  于是**注入一个不交易的主体，行情逐点不变**（实测最大差 = 0）。
- **主体随机流按 `(seed, 序号)` 播种**，不用共享种子池 spawn，
  所以增删主体不会扰动其他主体的流。

### 7.1 怎么确认你手里的产物是"这一版代码跑出来的"

**这一条是给"拿别人结果做判断"的人写的。** 项目踩过一次很贵的坑：
改了内核代码之后重跑，因为**缓存键没覆盖"把配置翻译成行为的那段代码"**，
结果那次"重跑"命中了旧缓存，产出的数字与改之前**逐位相同**——
而当时没有任何机制能区分"改动无效果"和"根本没重跑"。

现在有三道锁，**你不需要相信谁的口头保证**，跑一条命令即可：

```bash
python scripts/selfcheck.py     # 只读产物、不看生成器代码的独立检查
```

它会做这些事，任一项不过就返回非零：

- **产物新鲜度**：一键复现跑过的步骤必须产出比开跑时间更新的文件（防旧产物冒充）；
- **承重数字对账**：报告里的关键数字逐个与 `out/*.json` **现算值**比对
  （按数值+容差，不按格式串），且**同一个量在报告里出现多处时处处一致**；
- **缓存签名**：`out/stage*_cache.json` 头部记录着写它时的代码签名，
  签名不符会**整份作废**而不是将就复用；
- **不许漏出** `nan`/`None`/`inf`，不许残留没替换掉的模板占位符。

想从头重跑并让所有产物与当前代码对齐：

```bash
python -u scripts/reproduce_all.py --with-mutation
# 开跑前会自动把现有产物快照到 out/_archive/<时间戳>/
# 所以"改前 vs 改后"随时可对比；估时取自上次实测，不是手写的
```

**如果你看到的结论与这份手册不一致，先跑 `selfcheck.py`，
再看 `out/repro_timings.json` 的 `measured_at` 与产物 mtime。**
不要用"看起来合理"来判断一个数字是不是新的。

## 9. 已知局限（写策略前必须知道）

| 局限 | 影响 |
|---|---|
| **冲击是线性/超线性的，真实市场是凹的**（平方根律） | **大单的成本会被高估**。本项目已定位根因：本模型盘口累计深度剖面接近线性（γ≈0.8），真实市场是凸的（γ≈2）。执行类策略的结论要打折看。<br>⚠️ **二期动过这一条，但默认环境没变**：阶段6 加了元订单拆分 + 自适应流动性，机制确实在工作（ΣACF 配对差 +1.681、t=6.11），可是**主指标 k 反而从 0.665 走到 0.910，更远离 0.5**；阶段8 叠加 Hawkes 后 k 到 **0.481**（几乎精确是平方根律），但那是单一实验的结果，不是默认参数。**所以你在默认场景里跑执行类策略，仍然要按"大单成本被高估"来读。** 详见 `docs/交易世界二期-交付报告.html` 第 4、6 节 |
| **没有 ADL / 保险基金 / 跨保证金** | 清算场景里"清算不完"是模型边界，不是市场性质 |
| **没有手续费、资金费率、借券成本** | 高频做市类策略会被系统性高估 |
| **主体是同质的、规则固定的** | 你的策略不会遇到"别人也在学习/适应"的情况 |
| **1 tick ≈ 1 小时只是刻度** | 不要对延迟、队列位置做结论 |
| **σ 依赖主体数 N** | 换 `n_agents` 时，绝对量级会变；跨 N 比较只能看相对差值 |

**这些局限不会因为策略赚钱而消失。** 把上表放在结论旁边一起报，
比只报一个漂亮的 PnL 曲线有价值得多。
