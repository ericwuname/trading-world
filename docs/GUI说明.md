# 交易世界 · 桌面端使用说明

> 一个本地桌面应用：跑人工市场、写策略、看归因。
> 启动：`python scripts/gui.py`

---

## 0. 三十秒上手

```bash
PY=C:/Users/87465/.workbuddy/binaries/python/envs/py313/Scripts/python.exe

$PY scripts/gui.py                 # 开原生窗口（推荐）
$PY scripts/gui.py --browser       # 用系统浏览器代替原生窗口
$PY scripts/gui.py --no-window     # 只起服务，不开界面（自动化 / 远程调试）
```

打开后：左边选**场景 + 策略**，点 **▶ 运行**，右边看结果。

## 1. 它是怎么搭起来的（以及为什么）

| 层 | 技术 | 为什么这么选 |
|---|---|---|
| 窗口 | **pywebview**（Windows 用系统自带的 WebView2） | 不打包浏览器，安装体积小；缺依赖时自动退回系统浏览器，功能完全一样 |
| 后端 | **Python 标准库 `http.server`** | 不引入 Flask/Django。模拟本来就是 Python，没必要为了一层 HTTP 多加一个框架 |
| 前端 | **单个 HTML 文件，零外部依赖** | 没有 npm / 打包步骤；**不加载任何 CDN**，离线也能用 |
| 图表 | **手写 canvas** | 不引 Chart.js。1200 个点的折线、直方图 + 正态叠加、柱状图，手写足够且可控 |

**一句话：窗口是外壳，不是功能。** 开不出原生窗口时，浏览器里跑的是同一个应用。

## 3. 两种运行类型

### 纯市场（`kind=market`）

只跑市场本身，**不放策略**。用来看"这个市场像不像真实加密市场"。

### 策略实验（`kind=strategy`）

流程是：**先跑预热 → 再注入策略 → 再观测**。

为什么要分两段：让所有策略共享同一段预热行情，起点一致。
如果策略参与预热，每个策略会把市场带到不同状态，
后面的对比就不再是"同一初始条件下的差异"了。

## 4. 写自己的策略

勾上 **「用自定义代码」**，直接在界面里改：

```python
from tw.strategy import Strategy

class MyMaker(Strategy):
    def __init__(self, *args, half_spread_bp=12.0, qty=2.0, **kw):
        super().__init__(*args, **kw)
        self.half, self.qty = half_spread_bp, qty

    def on_tick(self, ctx):
        mid = ctx.mid
        if mid is None:
            return None
        ctx.cancel_all()                       # 每 tick 撤旧挂新
        return ctx.quote(mid * (1 - self.half / 1e4),
                         mid * (1 + self.half / 1e4), self.qty)
```

### 可用的钩子

| 钩子 | 何时调用 | 用途 |
|---|---|---|
| `on_start(ctx)` | 第一次决策前一次 | 参数校验、建缓冲区 |
| `on_tick(ctx)` | 每个 tick | **主决策**，返回 `None` / 一个订单 / 一组订单 |
| `on_fill(fill)` | 自己的订单成交时 | 推进执行进度 |
| `on_end(ctx)` | 模拟结束时一次 | 收尾计算（执行类策略算完成度） |

### `ctx` 里有什么

```python
# 行情
ctx.tick, ctx.mid, ctx.best_bid, ctx.best_ask
ctx.spread, ctx.spread_bp, ctx.fundamental
ctx.mid_lag(n), ctx.momentum(n), ctx.mid_std(n)

# 账户
ctx.cash, ctx.inventory, ctx.available_cash, ctx.available_inventory
ctx.open_orders, ctx.n_open_orders, ctx.equity(), ctx.pnl()

# 下单（自动预留制记账 + tick 网格吸附）
ctx.buy(price, qty) / ctx.sell(price, qty)
ctx.market_buy(qty) / ctx.market_sell(qty)
ctx.limit_at(side, offset_bp, qty)
ctx.quote(bid, ask, qty)      # 双边，返回实际生效的订单列表
ctx.cancel_all()
```

### ⚠️ 安全提醒

**这段代码会在你的本机直接执行，没有沙箱。**
进程内的 Python 沙箱做不干净（`__builtins__` 到处可达），所以这里没有假装做。
不要运行来源不明的策略代码。

服务本身只绑定 `127.0.0.1`，且所有 API 都要带一次性 token；
再关上 `TW_GUI_ALLOW_CODE=0` 可以彻底禁用代码执行能力。

## 5. 结果怎么读

界面上每个卡片都带一段说明，这里只重复三条最容易踩的：

### ① 只看均值会在噪声上编故事

「漂移 h20」后面括号里是 **t 值**。`|t| < 2` 一律当噪声，**不要解读**。

### ② PnL 必须拆开看

```
合计 = 价差捕获（本事） + 库存变动（行情） + 底仓重估（行情）
```

一个**完全不交易**的账户也会有「底仓重估」。实测过一例：
TWAP 执行策略合计赚了 14.98 万，其中「价差捕获」只有 **−1,699**——
剩下全是建仓期间市场涨了。只看合计会把平庸的执行算法看成优秀策略。

### ③ 恒等式残差必须接近 0

「策略表现」页最后一行有 `恒等式残差`。它是 `PnL三分解之和 − 权益变化`，
数学上恒等于 0。**它不为 0 就说明评估代码坏了，此时整张表都不可信。**

## 7. API（给脚本 / 自动化用）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/meta` | 场景、策略、默认值、限额 |
| POST | `/api/run` | 建作业，返回 `{job_id}`；**参数错误在这里就报** |
| GET | `/api/job/<id>` | 状态 + 进度 + 结果 |
| GET | `/api/job/<id>/series` | 时序（已下采样） |
| POST | `/api/job/<id>/cancel` | 请求取消 |
| GET | `/api/jobs` | 本次会话的作业列表 |
| GET | `/api/real/<symbol>` | 真实行情统计 + 序列 |
| GET | `/api/export/<id>.csv` | 导出指标 CSV（带 BOM，Excel 打开不乱码） |

除 `/` 与 `/static/*` 外，**所有请求都要带 `X-TW-Token` 头**，
token 由启动器打印在控制台。

## 8. 性能与限额

| 限额 | 值 | 为什么 |
|---|---|---|
| 观测 tick | ≤ 60,000 | 日志数组大小与运行时长直接相关 |
| 预热 tick | ≤ 20,000 | 同上 |
| 主体数 | ≤ 1,500 | 每主体每 tick 一次决策，成本线性 |
| 批量组合数 | ≤ 300 | 防止手滑点出一万个组合 |
| 批量总规模 | ≤ 300 万 tick·次 | **这才是真正的成本驱动量**——20 次 × 5 万 tick 比 280 次 × 1000 tick 贵得多 |

参考速度：300 主体、7500 tick 约 5 秒（单核）。
工作线程默认 `min(4, CPU//2)`——模拟是纯 CPU 密集，开太多只会互相抢核。

## 9. 排错

| 现象 | 原因 / 处理 |
|---|---|
| 打开是白屏、提示"缺少访问令牌" | 直接访问了不带 `?token=` 的地址。用启动器打印的完整链接 |
| 提示"只接受来自本机的请求" | 用了非回环 Host。别用 `localhost.` / 内网 IP 访问 |
| "无法连接后端" | 服务没起来（端口被占？）。看控制台输出 |
| 原生窗口开不出来 | 缺 WebView2 运行时或 pythonnet → 自动退回浏览器；也可 `--browser` |
| 策略"什么都没做" | 看「策略表现」里的 `策略异常` 计数——异常会被吞掉并计数，不会崩模拟 |
| 订单被裁剪 | 现金/持仓不够时**订单会被裁小**而不是拒单。看 `被拒/裁剪` 与 `available_cash` |
| 批量对照很慢 | 单线程顺序跑。调小「每次 tick」或减少种子数；或加大 `--workers` |

## 10. 已知局限

界面里能看到的每一条结论，都受下面这些约束——**它们不会因为策略赚钱而消失**：

| 局限 | 对结论的影响 |
|---|---|
| 冲击是线性/超线性的，真实市场是凹的（平方根律） | **大单成本会被高估**，执行类策略的结论要打折 |
| 没有手续费 / 资金费率 / 借券成本 | 高频做市类策略会被**系统性高估** |
| 没有 ADL / 保险基金 / 跨保证金 | 清算场景里"清算不完"是模型边界 |
| 主体同质、规则固定 | 不会遇到"别人也在学习适应"的情况 |
| 1 tick ≈ 1 小时只是刻度 | 不要对延迟、队列位置做结论 |
| σ 依赖主体数 N | 换 N 时绝对量级会变，跨 N 只能比相对差值 |

更完整的说明见 `docs/策略测试手册.md`。
