## 1. 为什么现在才做合并

A 线（EA.1/EA.1b）证明了一件事：**阶段8 报出的 k 改善里有一半是 λ̄ 标尺错误放大的**
（宣称 1.395→0.481，实际 1.395→0.947）。这意味着：

**在统一标尺之前做"A+B+C 叠加"，等于把两类误差叠在一起**——
一类是"机制到底有没有生效"，一类是"标尺偏了多少"。
两者混在一起之后，任何结果都无法归因。所以先做 A、B、C 各自的干净测量，
再在这里统一口径做合并。这就是"为什么现在才做"。

## 2. 合并规则（先定死，不许事后改）

### 规则一：λ̄ 必须**在同一配置上**标定

这是 A 线的直接结论。E8.2 的错法是"在裸 `Market` 上标定、在带 `MM_KW` 的市场上使用"。
合并时的做法：

> **每一条臂用自己的市场配置（含元订单覆盖、含 MM_KW）标定 λ̄，
> 且标定窗口 = 实验窗口。**

标定窗口也要对齐：E8.2 用 `n_ticks=3000, warmup=500`（窗口含瞬态，偏高约 7%），
实验窗口却是 `[6000, 6400)`。合并时一律用**同一窗口**。

### 规则二：合并只做"加法"，不做"重调参"

不为了让 k 好看去找一组新参数。三条线各自的参数是：

- **A（Hawkes）**：`branching=0.6, beta=0.15`，λ̄ 同市场口径标定
- **B（元订单覆盖）**：`meta_shares = {chartist: 0.4, zero_intel: 0.5, fundamentalist: 0.5}`，`META_CFG` 不变
- **C（多资产修复）**：`short_headroom = 3.0`（即默认的修复后行为）

### 规则三：每个臂都要报"机制有没有真的生效"

只看 k 不看活跃度，正是 E8.2 翻车的形态。每个臂都报：
ρ̄、平均活跃主体数、**稀疏化真正生效的 tick 占比**、成交/tick。
其中"稀疏化生效占比"是本次新增的**体检指标**——它一旦接近 0，
说明机制撞在上限上哑火了，那个臂的 k 就不许被解释成"聚集性的效果"。

### 规则四：判据事先定死

- **k**：以分期清算的**因果滑点**幂律指数为主指标，|k−0.5| 越小越好
- **传导链条**：沿用 E11.1 的判据（冲击后配对差均值超出冲击前均值 ± 3×标准误），
  **判据不动**，只换配置

## 3. 组合方式与理由

| 臂 | 配置 | 想回答什么 |
|---|---|---|
| J1 | 阶段6 基线（仅图表派元订单 + 自适应流动性） | 合并的**共同基线** |
| J2 | J1 + B 的三类覆盖 | B 单独贡献多少 |
| J3 | J2 + A 的修正 Hawkes（同市场口径 λ̄） | A 在 B 之上还有多少边际贡献 |
| J4 | J3（阶段11 场景） | 至暗时刻的链条判定环节数有没有变化 |

**J4 与 J1–J3 不是同一类实验**：J1–J3 是单资产的清算冲击实验（测 k），
J4 是双资产的"至暗时刻"链条（测 6 个环节的传导判定）。分开报，不混。

## 4. 合并里**不能**做的事（事先声明）

1. **不能把 C 塞进 k 值检验。** C 的修复（`short_headroom`）只作用于配对交易者，
   而配对交易者住在多资产市场里；k 值检验是**单资产**实验。
   所以 C 对这个 k 数字的贡献是**零**，不是"很小"。报告里必须这么写。
2. **不能拿 J1–J3 与阶段8 的 0.481 直接比。** 那个数是错标尺的产物
   （可比对象是 EA.1b 的 0.947）。
3. **不能因为 k 没到 0.5 就只报"机制已实现"。** 差多少就报多少。

- 阶段6 基线 k = 1.251
